# 3.1 Живая приёмка (последовательно, в самом конце)

Единственный этап, трогающий живые данные. Параллельных прогонов не выдерживает.

**Предусловия:** этап 1.1 сдан (иначе прогон деструктивных инструментов ничем не ограничен);
бандл пересобран — устаревший `dist` уже маскировался под флак и стоил часа диагностики
(канон, §8.1).

## Область

52 мутирующих инструмента, начиная с 14 деструктивных. Каждый — по инварианту канона: эффект
проверяется **независимым чтением**, а не ответом самой мутации.

Деструктивные проверяются на сущностях, созданных этим же прогоном, и только на них — это то,
что обязана гарантировать оснастка 1.1, а не дисциплина исполнителя.

## Отдельно проверить

- **v2/v3** по факту ответа, а не по коду: категория обязана ходить в версию из таблицы.
- **`GET /v3/filters`** — путь взят по аналогии с механикой референсного Python-клиента, а не из
  документации; это непроверенная гипотеза, помеченная комментарием в коде.
- **Существует ли `DELETE /v3/filters/{id}`** — инструмента `delete_filter` у нас нет,
  асимметрия CRUD ответом API не подтверждена.
- **`warnings` в бою** — введён 3.0.0, живьём проверен одним сценарием.

## DoD

- отчёт файлом с перечнем расхождений; каждое либо исправлено с регрессионным тестом, либо
  заведено задачей;
- прогон не вышел за пределы `TEST` — доказано журналом оснастки 1.1, а не утверждением;
- созданные сущности перечислены и убраны (или названы как оставленные).
