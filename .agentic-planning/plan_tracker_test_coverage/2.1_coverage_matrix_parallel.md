# 2.1 Матрица покрытия и закрытие дыр (параллельно, после 1.1)

## Первый шаг — матрица, а не тесты

Построить таблицу «инструмент × С-1..С-7» по всем 92 и положить файлом на диск. Пока её нет,
любое утверждение о покрытии — оценка. Строка обязана нести либо «покрыт тестом X», либо
«сознательно не покрывается, причина».

Матрица строится скриптом, а не вручную: она понадобится ещё раз при каждом новом инструменте,
и ручная версия протухнет к следующему релизу. Скрипт кладётся в `scripts/`.

## Нарезка на пакеты — по категориям

Категории не пересекаются по файлам, что делает их готовыми границами (проверено предыдущим
планом). 59 инструментов без интеграционного теста распределяются по владеющим категориям.

Приоритет внутри пакета: сначала мутирующие, среди них — деструктивные.

## Что проверяет интеграционный тест (сверх unit)

- **С-4, верность API**: путь, метод и **версия** (issues/queues/comments/links/transitions/
  changelog — v3; attachments/checklists/components/projects/worklogs — v2). v2 вместо v3 обычно
  отвечает 200 и молча отдаёт другую форму — unit-мок этого не ловит по построению.
- **С-6, поведение на границах**: пагинация (тип постранички фиксируется явно для каждого
  эндпоинта — они различаются), batch со смешанным исходом, лимиты.
- **Новое от 3.0.0**: `warnings` присутствует только когда непусто; форма `details.fields`;
  детектор выключен там, где обязан (режим `links`, `raw_api_request`).

## Пять инструментов без unit-теста

`upload_attachment`, `download_attachment`, `delete_attachment`, `get_thumbnail`, `delete_worklog`.
Первые четыре — бинарные данные, класс, где мок дешевле всего расходится с реальностью:
кодировка, `Content-Type`, размер, поток против буфера. Для них unit-тест обязателен, но
достаточным не считается — они же идут в живую приёмку 3.1.

## DoD

- матрица построена скриптом, лежит файлом, у каждого из 92 инструментов заполнена строка;
- 59 дыр либо закрыты, либо каждая имеет записанную причину не закрывать;
- для каждого пагинируемого эндпоинта тип постранички зафиксирован явно.
