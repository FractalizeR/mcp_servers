# Пакет 1.1 — Диагностируемое расхождение `tools/list` (sequential)

**Зависит от:** —
**Модель исполнителя:** старшая (диагностика неизвестной причины, а не правка по образцу).

## Мотивация

Четыре из шести последних падений релиза — «два последовательных `tools/list` в одном процессе
вернули разные списки». Обе ассерты сравнивают строки и печатают **только факт**:

```
482:      assert(
483:        JSON.stringify(first.result?.tools) === JSON.stringify(second.result?.tools),
484:        'два последовательных tools/list вернули разные списки tools'
485:      );
```

За четыре падения в логах CI нет ни байта о характере расхождения. Локально не воспроизводится.
Пока не известно, **чем** списки отличаются, любое исправление назначается наугад.

## Что уже исключено (проверять заново не нужно)

- `ToolSorter.sortByPriority` — чист (сортировка копии, code point, стабильный `Array.sort`).
- `BaseTool.getDefinition()` — кеширует определение в поле экземпляра (`base-tool.ts:78-108`).
- Ленивой дорегистрации нет: `registerToolFromContainer` не вызывается ни в одном сервере.
- Кеш turbo: обе задачи `cache: false`.

## Что делаем

1. **Ассерта становится диагностической.** При расхождении отказ обязан содержать:
   длины обеих строк; индекс первого различающегося байта с окном контекста вокруг него;
   разницу множеств имён инструментов (только в первом / только во втором); разницу порядка
   при совпадающих множествах. Образец подхода — уже существующий `waitForStderrSubstring`,
   который печатает накопленный stderr вместо «не дождались».
2. **Диагностика печатается в stdout процесса теста**, чтобы попасть в лог GitHub Actions
   без дополнительных флагов.
3. **Стресс-воспроизведение.** Прогон пары `tools/list` в цикле против собранного бандла,
   на Linux (контейнер или раннер), под нагрузкой (параллельно с `npm run test`), не только
   на mac. Цель — поймать расхождение локально. **Отрицательный результат фиксируется как
   результат**: «на N прогонах в таких-то условиях не воспроизведено» — это данные, а не неудача.
4. **Если расхождение поймано** — приложить полный вывод диагностики к отчёту пакета. На этом
   пакет закончен: устранение причины планируется отдельно, по добытым данным.

**Чего НЕ делаем:** не меняем сценарии, не выносим общий код (пакет 3.1 соседнего плана),
не переводим raw-wire на официальный `Client`, не правим тайминги (это пакет 1.2).

## Definition of Done

1. Искусственно подсунутое расхождение (например, временная мутация одного имени во втором
   ответе на стороне теста) даёт отказ, из текста которого **видно, что именно разошлось**.
   В отчёте — этот вывод дословно. Временная мутация после проверки убрана.
2. Диагностика присутствует в обоих скриптах всех трёх серверов; проверяется чтением диффа,
   а не количеством строк.
3. Стресс-прогон выполнен, его условия (платформа, число итераций, наличие нагрузки) и результат
   названы в отчёте.
4. `npm run test:raw-wire` и `npm run test:smoke:server` на трёх серверах проходят.
5. Список сценариев до и после совпадает поимённо.
