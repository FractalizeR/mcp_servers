## Таблица B — все ожидания по времени в скриптах, поднимающих процессы

**Чем получено:** `grep -rn "sleep(\|setTimeout(" packages/servers/*/scripts/*.ts`,
`grep -rn "_MS *=\|_TIMEOUT"` там же, **плюс чтение окружающего кода каждой строки** — в редакции 1
классификация делалась по номеру строки без контекста и оказалась неверной для четырёх строк
из шести. Отдельно проверено, что процессы не поднимаются больше нигде:
`grep -rln "spawn(\|execSync(" --include=*.test.ts packages/*/*/tests` → пусто; каталогов
`scripts/` во `framework/*` нет.

**Чего этот способ не видит:** ожидания, выраженные не таймером (цикл повторов с фиксированным
числом попыток, блокирующий `execSync`); таймауты, переданные ребёнку через env
(`REQUEST_TIMEOUT: '5000'` — это таймаут HTTP-клиента внутри сервера, не ожидание харнесса);
флак, приходящий не из таймингов (сеть, npm, ресурсы раннера).

| Файл (× 3 сервера) | Место | Что | Роль | Правка |
|---|---|---|---|---|
| `raw-wire-test.ts` | `STARTUP_DELAY_MS = 900` | `sleep` в `withServer` | **ожидание старта** (единственное) | убрать |
| `raw-wire-test.ts` | `close()` | `sleep(300)` перед SIGKILL | ожидание останова | по событию `exit` |
| `raw-wire-test.ts` | `RESPONSE_TIMEOUT_MS = 8000` | верхний таймаут ответа | предел | поднять до 20 000 |
| `smoke-test-server.ts` | shutdown основного процесса | `sleep(2000)` перед SIGKILL | **ожидание останова** | по событию `exit` |
| `smoke-test-server.ts` | `finally` второго процесса | `sleep(1000)` перед SIGKILL | **ожидание останова** | по событию `exit` |
| `smoke-test-server.ts` | перед первым запросом | — | **ожидания старта НЕТ** | — |
| `smoke-test-server.ts` | `RESPONSE_WAIT_TIMEOUT_MS = 10000` | таймаут ответа | предел | ➖ |
| `smoke-test-server.ts` | `STDERR_PATTERN_TIMEOUT_MS = 10000` | событийное ожидание stderr | уже событийное | ➖ |
| `smoke-test-server.ts` | `TIMEOUT_MS = 40000` | таймаут всего теста | предел | поднять: запаса нет |

**Исправление редакции 1:** обе паузы в `smoke-test-server.ts` — **ожидания останова** в блоках
завершения, а не старта. Ожидание старта там убрано коммитом `39ef0db3`, на его месте стоит
комментарий «Фиксированной паузы перед первым запросом больше нет: запись в stdin буферизуется
ОС-пайпом…». Проверено во всех трёх серверах.

**Арифметика `smoke-test-server.ts`:** `main()` оборачивает в `TIMEOUT_MS = 40000`
последовательность из четырёх окон по 10 000 (2 × `RESPONSE_WAIT_TIMEOUT_MS` в `runSmokeTest`
+ `STDERR_PATTERN_TIMEOUT_MS` и `RESPONSE_WAIT_TIMEOUT_MS` в `runDeprecatedEnvVarSmokeTest`).
Худший случай ровно 40 000 плюс два `spawn` и разбор трёхмегабайтного бандла — запаса нет,
глобальный таймаут сработает раньше конкретного и подменит диагностируемое сообщение.

**У `raw-wire-test.ts` глобального таймаута нет вовсе**, а `withServer` вызывается 17 раз.

## Таблица C — гейт depcruise: факт, не гипотеза

ни одно правило не матчится. Срабатывает только `no-circular` с `severity: warn`, код возврата 0.
