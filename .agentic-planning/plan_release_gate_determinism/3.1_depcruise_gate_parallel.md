# Пакет 3.1 — Живой гейт архитектурных границ (parallel)

**Зависит от:** 2.1 (после унификации проверка вызывается одинаково локально и в CI)
**Модель исполнителя:** средняя.
**Статус:** требует решения пользователя — брать в объём этого плана или вести отдельной задачей.

## Факт (подтверждён независимо, дважды)

Все архитектурные правила в `.dependency-cruiser.cjs` заданы как `path: '^packages/…'`
(строки 23, 26, 35, 38, 47, 50, 59, 62, 75, 78, 92, 95, 104, 107). Скрипт каждого workspace —
`depcruise src -c ../../../.dependency-cruiser.cjs` — исполняется из каталога пакета, где
depcruise репортит `source` вида `src/index.ts` и `../../servers/…`. Ни один source не начинается
с `packages/`, поэтому **ни одно архитектурное правило не может сматчиться никогда**. Срабатывает
только `no-circular`, и та с `severity: warn` — код возврата 0.

Проверено: сессией `MCP dev interface planning` (временный запрещённый импорт из `core` в
`servers` → «no dependency violations found») и независимо ревьюером этого плана
(`npx depcruise src --output-type json`: 699 модулей, ни одного source с префиксом `packages/`,
две находки `no-circular` уровня warn).

Граф зависимостей, объявленный в `CLAUDE.md` как критическое правило монорепозитория
(`infrastructure → cli/core → yandex-tracker`, запрет обратных зависимостей и импортов из
серверов во framework), машинно не контролируется — ни локально, ни в CI. Это тот же класс
дефекта, что чинит пакет 2.1: гейт, который выглядит работающим и не работает.

## Что делаем

1. Выбрать место починки — инвокация (запускать из корня монорепозитория, чтобы пути совпадали
   с regex) или правила (переписать под пути относительно пакета). **Один способ на весь
   монорепозиторий**, иначе разъедется снова. Учесть, что соседняя ветка уже починила инвокацию
   для своего пакета `dev-client` в его границах — решение должно с этим сойтись, а не
   конфликтовать.
2. Проверить, что корневой `depcruise:root` (`depcruise packages --validate`) валидирует именно
   тот граф, который объявлен в `CLAUDE.md`.
3. Устранить нарушения, вскрывшиеся после включения живого гейта. **Их количество заранее
   неизвестно** — гейт был мёртв неизвестно сколько. Если нарушений больше нескольких, пакет
   останавливается и список выносится пользователю: починка накопленного — не то же самое,
   что починка гейта, и в объём этого плана не входит.

## Definition of Done

1. Запрещённый импорт через границу графа **ловится**: временный импорт → красный `depcruise`
   → импорт убран → зелёный. В отчёте — обе команды и их вывод.
2. Проверка одинаково работает локально и в CI (после пакета 2.1 это один и тот же вызов).
3. Список существующих нарушений приложен к отчёту, их число названо явно (в том числе если оно
   равно нулю).
4. `npm run validate` в корне проходит.
