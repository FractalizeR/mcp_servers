# План: детерминизм релизного гейта

**Задача.** Пуш в main роняет `semantic-release` с непредсказуемой вероятностью. Убрать причину,
а не симптом.

**Статус:** редакция 2, после ревью (`native-claude`, интерфейс `dvizh-vr-review:comprehensive`).
Редакция 1 опиралась на неверный диагноз и переписана целиком; что изменилось — в конце файла.

## Диагноз (снят с логов прогонов, а не с диффа)

Шесть последних падений `release.yml`, тексты получены `gh run view --log-failed`:

| Прогон | Дата | Коммит | Что упало |
|---|---|---|---|
| 32230658808 | 08-19 | `4c3c04c` | `два последовательных tools/list вернули разные списки tools` (raw-wire, tracker) |
| 32220354956 | 08-19 | `c5b5931` | `Два последовательных tools/list вернули РАЗНЫЙ список` (smoke:server, tracker) |
| 31951214907 | 08-16 | `92ff147` | оба текста сразу (tracker) |
| 31949325849 | 08-16 | `a457bae` | `…вернули РАЗНЫЙ список` (smoke:server, **wiki**) |
| 31899617715 | 08-15 | `13391b9` | `did not print a TOOL_DISCOVERY_MODE warning` (ticktick) |
| 31884146433 | 08-15 | `cac6fad` | то же (ticktick) |

**Четыре падения из шести — буквально «два последовательных `tools/list` в одном процессе вернули
разные списки».** Ни в одном из шести нет сигнатуры «Таймаут ожидания ответа». Два падения по
времени (08-15, ticktick) — ожидание stderr, и его уже сделал событийным коммит `39ef0db3`
(08-15); после него этот класс отказов не повторялся.

Коммит `7f7f2302` («детерминированный порядок tools/list») выкатился 08-16 в 14:03 — **оба
падения 08-19 произошли после него.** Значит, порядок он починил, а проблему нет.

Формулировка пользователя «недетерминизм tools/list» была точной буквально. Редакция 1 этого
плана объявляла её уже решённой и чинила тайминги — то есть лечила то, что по логам даёт
0 из 6 падений.

### Причина неизвестна, и это состояние плана, а не пробел

Очевидные кандидаты проверены по коду и **исключены**:

- `ToolSorter.sortByPriority` чист: сортирует копию, приоритет первым ключом, имена сравниваются
  по code point (не `localeCompare`), ничьих при уникальных именах нет.
- `BaseTool.getDefinition()` **кеширует** результат первого вызова в поле экземпляра
  (`base-tool.ts:78-108`) — генерация JSON Schema из Zod повторно не выполняется. Гипотеза
  ревьюера про пересборку схемы на каждый вызов не подтвердилась.
- Ленивой дорегистрации инструментов нет: `registerToolFromContainer` не вызывается ни в одном
  из трёх серверов (grep по `packages/*/*/src`).
- Кеш turbo ни при чём: `test:smoke:server` и `test:raw-wire` объявлены `cache: false`.

Обе ассерты сравнивают строки и печатают **только факт расхождения** — ни позиции, ни разницы
составов, ни длин. За четыре падения в логах нет ни байта о характере расхождения. Локально
не воспроизводится (шесть последовательных `tools/list` против собранного бандла tracker дали
идентичные списки).

**Отсюда структура плана: сначала добыть свидетельство, потом чинить.** План, который сейчас
назначил бы исправление, назначал бы его наугад.

## Установленные факты

- **Сервер при успешном старте молчит** — ни stdout, ни stderr при `LOG_LEVEL=error` до первого
  запроса (проверено запуском бандла tracker с `BASE_ENV` харнесса). Маркера готовности нет.
- **Сервер с битым env падает сразу**, печатая ошибку и стек в stderr.
- **Ожидание старта осталось только в `raw-wire-test.ts`** (`STARTUP_DELAY_MS = 900`).
  В `smoke-test-server.ts` его убрал `39ef0db3`; оставшиеся там `sleep(2000)` и `sleep(1000)` —
  **ожидание останова** в `finally` (SIGTERM → пауза → SIGKILL). В редакции 1 они были
  классифицированы неверно.
- **Запись в stdin до старта ребёнка безопасна** — данные лежат в буфере пайпа; это уже
  используется в `smoke-test-server.ts` и проходит релизы.
- **`npm run knip` в `ci.yml` не исполняет ничего:** ни один workspace не объявляет скрипт `knip`,
  `turbo run knip` даёт «0 successful, 0 total» и код 0.
- **Гейт `depcruise` мёртв** — подтверждено независимо: все архитектурные правила в
  `.dependency-cruiser.cjs` заданы как `path: '^packages/…'`, а `depcruise src` из каталога пакета
  репортит `source` вида `src/index.ts`; ни один source не начинается с `packages/`, срабатывает
  только `no-circular` с `severity: warn` (код возврата 0).

## Принятые решения

| Развилка | Решение | Обоснование |
|---|---|---|
| Что делать первым | **Сделать ассерты диагностическими** | Единственный способ узнать характер расхождения — снять его со следующего падения на раннере. Правка дешёвая и в тех же шести файлах |
| Чинить ли причину в этом плане | **Нет: пакет фикса планируется после пакета 1.1** | Причина неизвестна; назначать исправление сейчас — гадание |
| Критерий «починили» | Не «N зелёных прогонов» | Событие даёт ~4 падения на десятках прогонов и не воспроизводится локально: двадцать зелёных прогонов на mac не отличают «починили» от «не поймали» |
| Ожидание старта в raw-wire | Убрать `STARTUP_DELAY_MS`, первый запрос слать сразу | Маркера готовности нет; готовность подтверждает ответ. Это гигиена и −15 с холостого сна на сервер, **не** устранение причины падений |
| Ожидание останова (оба скрипта) | SIGTERM → событие `exit` → SIGKILL по пределу | `sleep(300)`/`sleep(1000)`/`sleep(2000)` не гарантируют ничего |
| Кто владеет набором проверок | `scripts/validate.sh`, `ci.yml` его зовёт | Второго списка шагов быть не должно — он и разъехался |
| Переводить ли raw-wire на официальный `Client` | **Нет** | Ограничение соседней ветки: эти тесты проверяют поведение SDK, прогон через клиент того же SDK — тавтология |
| Дедупликация шести файлов | **Не в этом плане** | Пакет 3.1 плана `plan_mcp_dev_interface` соседней ветки; согласовано между сессиями |
| `test:integration` пакета `dev-client` | В `validate.sh` не добавлять | Требует `claude` CLI и запись MCP-клиента; релизный CI не должен зависеть от сети и токенов |

## Контракты (сигнатуры, без реализации)

Новых модулей не заводится. Три изменения формы внутри каждого харнесса:

```
assertToolsListStable(first, second): void
//   при расхождении отказ содержит: длины обеих строк, индекс первого
//   различающегося байта с окном контекста, разницу множеств имён
//   (только в первом / только во втором) и разницу их порядка

request(id, method, params?): Promise<JsonRpcResponse>
//   отклоняется раньше таймаута, если ребёнок закрылся или упал;
//   текст отказа включает код выхода, сигнал и накопленный stderr

close(): Promise<void>
//   SIGTERM → ожидание события 'exit' → SIGKILL по истечении предела
```

Образцы для второго и третьего уже есть в `smoke-test-server.ts` (`waitForJSONRPCResponse`
слушает `close`/`error`) — берутся оттуда, а не пишутся заново.

## Кейсы и граничные условия

- **Ребёнок умер до записи в stdin** → `EPIPE`. Нужен обработчик `error` на `child.stdin`, иначе
  необработанное исключение вместо внятного отказа.
- **Ответ приходит частями** — парсер построчный и накапливает буфер; не регрессировать.
- **Сценарий 4 raw-wire** (неподдерживаемая версия протокола первым сообщением нового соединения)
  особого обращения не требует: удаление паузы порядок сообщений не меняет.
- **Сценарии 10–13** (подставной `http.Server`) уже событийны — `server.listen(0, …, resolve)`.
- **Арифметика таймаутов считается внутри каждого скрипта отдельно.** В `smoke-test-server.ts`
  худший случай ровно `TIMEOUT_MS = 40000` при четырёх окнах по 10 000 — глобальный таймаут
  сработает раньше конкретного и заменит диагностируемое сообщение на «Тест превысил таймаут».
  В `raw-wire-test.ts` глобального таймаута нет вовсе, а `withServer` вызывается 17 раз.

## Тестовый план

- Сценарии не добавляются и не меняются: сверка названий поимённо до и после.
- Стресс-воспроизведение (пакет 1.1): многократный прогон пары `tools/list` под нагрузкой,
  на Linux, а не только на mac. Отрицательный результат — тоже результат и фиксируется.
- Негативный кейс: запуск с битым env — отказ **сразу**, с текстом ошибки сервера, а не таймаут.
- `npm run validate` в корне проходит.

## Definition of Done всего плана

1. При расхождении двух `tools/list` в логе виден **характер** расхождения: длины, первый
   различающийся байт с контекстом, разница множеств имён и порядка. Доказано искусственно
   подсунутым расхождением, а не рассуждением.
2. В шести харнессах не осталось `sleep`, выражающих ожидание старта или останова процесса
   (проверяется grep).
3. Запуск с битым env даёт отказ с текстом ошибки сервера.
4. `ci.yml` исполняет `scripts/validate.sh` целиком; расхождения с `release.yml` перечислены
   и обоснованы; каждый шаг таблицы A либо исполняется, либо его отсутствие названо.
5. Запрещённый импорт через границу графа ловится `depcruise` — доказано временным импортом.
6. `npm run validate` в корне проходит.
7. Список сценариев обоих скриптов до и после совпадает поимённо.

## Риски

| Риск | Обработка |
|---|---|
| Следующее падение опять придёт без диагностики | DoD 1 требует доказательства на искусственном расхождении, а не «мы добавили вывод» |
| Расхождение перестанет воспроизводиться само | Диагностика остаётся в коде постоянно; отсутствие падений — не повод её снимать |
| Гигиена ожиданий будет засчитана как устранение причины | Явно записано в решениях: 1.2 — гигиена, причина не устранена |
| `test:coverage` покраснеет на первом же PR после унификации | Пороги не понижать молча: цифры выносятся пользователю (пакет 2.1) |
| Включение живого `depcruise` вскроет много накопленных нарушений | Пакет 3.1 останавливается и выносит список пользователю |
