# Починка дефектов, найденных сплошной сверкой маршрутов (2026-08-25)

Вход: `.agentic-planning/plan_tracker_fix_create_tools/4_ROUTE_SWEEP_2026-08-25.md`
(сверка) и живые пробы того же дня. Каждый пункт ниже **подтверждён ответом боевого
API**, а не только чтением документации; опровергнутые сверкой гипотезы перечислены
отдельно, чтобы их не «чинили» повторно.

## Подтверждено живьём

| № | Инструмент | Ответ API | Причина |
|---|---|---|---|
| F1 | `update_project` | `428` | не передаётся обязательная версия |
| F2 | `update_component` | `428` | то же |
| F3 | `update_board` c `filter` | `422` «Невозможно сохранить некорректный фильтр» | схема шлёт `filter: {query}`, API ждёт карту «поле → значения» |
| F4 | `update_board` c `orderBy`/`orderAsc` без `filter` | `422` | схема разрешает комбинацию, которую API отвергает |
| F5 | `create_queue` c `issueTypes` | `400 Incorrect data format` | параметра нет в API; любой вызов с ним падает |

F1 и F2 означают, что оба инструмента не работали **никогда** — как и пятёрка,
починенная в предыдущем заходе. Их «зелёные» тесты на моках проверяли предписанное.

## Опровергнуто живой пробой — не чинить

- `update_board_column.limit` — доезжает и сохраняется (документация неполна).
- `create_queue.description` — доезжает и сохраняется (документация неполна).
- `update_board.useRanking`, `query` — сохраняются; «устарел» в документации сказано
  про влияние на поведение доски, а не про приём параметра.
- `PATCH /v3/queues/{id}` (`update_queue`) — маршрута нет в справочнике, но он живой
  и версии не требует.

## Не проверено, вынесено из объёма

- `update_global_field`: канонический маршрут документации — `PATCH /v3/fields/{id}?version=`,
  версию мы не шлём. Живая проба невозможна: рубеж прогона отклоняет правку чужого
  глобального поля, а своё не создаётся из-за незакрытого D10. **Правку контракта
  делать нельзя** — это была бы догадка ровно того рода, что породила разбираемые
  дефекты. Пункт остаётся открытым до закрытия D10.
- `DELETE /v3/components/{id}`, `DELETE /v3/fields/{id}` — маршрутов нет в справочнике,
  живьём не проверялись: прогон ничего не удаляет.

## Перечисление множества: кто ещё обязан слать версию

Утверждение «версию не шлют только эти три инструмента» опирается на таблицу
`/private/tmp/.../version-table.md` и на перечень канонических маршрутов документации,
где версия входит в запрос.

**Чем получено:** (1) grep по `httpClient.(post|patch|put|delete)<` во всех
`src/tracker_api/api_operations/**/*.operation.ts` — 40 мутирующих операций, из них
версию шлёт одна (`update-issue`) и ещё одна упоминает (`update-entity`);
(2) выборка канонических маршрутов из `docs-routes.json` по вхождению `version` —
12 маршрутов документации.

**Чего способ не видит:** версию, добавляемую слоем ниже (`HttpClient`/интерцептор);
версию, собираемую в util рядом с операцией; обязательность версии на стороне API,
когда она не отражена в каноническом URL (её даёт только живая проба — так и найдены
F1 и F2, у которых версия в URL как раз объявлена).

Пересечение множеств даёт ровно три наших инструмента: `update_project` (F1),
`update_component` (F2), `update_global_field` (вынесен из объёма выше). Остальные
девять версионных маршрутов документации (`issuetypes`, `priorities`, `resolutions`,
`statuses`, `fields/categories`, `queues/{}/triggers`, `versions`) инструментов у нас
не имеют.

## Решение по контракту версии

Версия добывается так же, как у `update_issue`: необязательный параметр вызывающего,
уходящий в query. Отличие: у проекта и компонента API её **требует**, поэтому при
отсутствии параметра операция читает текущую версию сама (GET перед PATCH) и шлёт её.

Обоснование: делать параметр обязательным — значит превращать «переименуй компонент»
в два вызова и ронять инструмент у любого вызывающего, который версию не отслеживает.
Прецедент лишнего GET перед правкой в пакете уже есть и обоснован в
`board-column-addressing.util.ts`. Цена решения — при не переданной версии правка
становится «последний выигрывает», и это обязано быть сказано в описании инструмента,
а не только в коде.

## Пакеты работ

Наборы файлов не пересекаются, пакеты независимы и выполнимы в любом порядке.

### Пакет A — версия проекта (F1)

Файлы: `src/tools/api/projects/update-project.schema.ts`,
`src/tools/api/projects/update-project.tool.ts`, `src/tools/api/projects/base-project.schema.ts`
(только если `queueIds`/`teamUserIds` объявлены там),
`src/tracker_api/dto/project/update-project.dto.ts`,
`src/tracker_api/api_operations/project/update-project.operation.ts`, их тесты.

- `version?: number` в схеме, описание — как у `update_issue`.
- Операция: версия не передана → чтение проекта, взятие `version`; далее
  `?version=<n>`. Метод оставить `PATCH`: живая проба показала, что 428 приходит
  именно от проверки версии, то есть PATCH маршрутизируется. Документация называет
  `PUT` — расхождение зафиксировать комментарием со ссылкой на страницу и проверить
  живьём после правки; если PATCH с версией не пройдёт, менять на `PUT`.
- Убрать из тела `queueIds` и `teamUserIds` — их нет в перечне документации
  (там `queues`, `name`, `description`, `lead`, `status`, `startDate`, `endDate`).

**DoD:** живой вызов правит имя проекта и возвращает `version+1`; тест на подстановку
версии из чтения; тест на передачу версии вызывающим; тест, что `queueIds` больше не
уходит в тело.

### Пакет C — фильтр доски (F3, F4)

Файлы: `src/tools/api/boards/update-board.schema.ts`,
`src/tools/api/boards/update-board.tool.ts`,
`src/tracker_api/dto/board/update-board.dto.ts`,
`src/tracker_api/api_operations/board/update-board.operation.ts`, их тесты.

- `filter` меняет форму с `{query?: string}` на карту «поле → значение или список
  значений»; форма снята чтением боевых досок (`{queue: ["DVIZHDEV"], resolution: ["empty()"]}`).
- `orderBy`/`orderAsc` без `filter` отклоняются **до** запроса, с текстом причины —
  как сделано в D11 для неоднозначной колонки: отказ рубежа лучше 422 из API.
- `query` и `useRanking` остаются: живая проба показала, что они доезжают.

**DoD:** живой вызов ставит доске фильтр по очереди и чтение это подтверждает;
тест на отказ при `orderBy` без `filter`; тест формы фильтра.

### Пакет D — `issueTypes` у создания очереди (F5)

Файлы: `src/tools/api/queues/create-queue.schema.ts`,

**DoD:** тест, что `issueTypes` не принимается схемой; живое создание очереди без него
