# Легаси-проекты и Entity-проекты — это один набор объектов (живая проба 2026-08-25)

## Что проверено

Сняты **оба списка целиком** (`fetchAll`), не выборкой:

| | `GET /v3/projects` (легаси) | `POST /v3/entities/project/_search` |
|---|---|---|
| Записей | 43 | 43 |
| Уникальных имён | 39 | 39 |
| Пересечение имён | **39** | **39** |
| Только в своём списке | 0 | 0 |

Идентификаторы разные, объекты те же:

| Имя | Легаси id | Id сущности |
|---|---|---|
| Сделка | `2` | `630daf9963b9a669b5d342f1` |
| Ипотека | `3` | `630daf9963b9a669b5d342f2` |
| Регистрация | `4` | `630daf9963b9a669b5d342f3` |
| ТКБ | `64` | `69b13e1e5c832930d3bdd945` |

Порядок числовых и hex-идентификаторов совпадает — это два представления одного
набора, а не два набора. Подтверждается интерфейсом Трекера: «Ипотека» и
«Регистрация» показаны внутри портфеля «Движ», а портфели существуют только в
новой модели.

## Отменённое утверждение

Ранее в этой сессии было сказано: «легаси — 74 объекта, множества не пересекаются,
удаление ослепит сервер». **Неверно.** Число 74 — количество досок из соседнего
запроса, перепутано при чтении. Сравнение делалось по выборке из восьми имён, а не
по полным спискам. Вывод, построенный на нём, снят этой пробой.

Метод, которым ошибка поймана: снять оба множества целиком и сравнить программно,
вместо того чтобы смотреть на первые записи.

## Следствие для удаления легаси

Данные не теряются: всё, что видно через `/v3/projects`, видно через Entity API.
Единственная реальная разница — **привязка очереди при создании и правке**: легаси
принимает `queues` ключом строкой, у Entity API `issueQueues` документирован как
доступный только для чтения, а в теле создания сущности поля очереди нет вовсе.
То есть это возможность старой модели, которую убрал сам Трекер, а не регрессия,
которую вносим мы.

Остальные различия (словарь статусов, формат дат ISO вместо `YYYY-MM-DD`,
непроверенная обязательность `version` у `update_entity`, нереализованный
`withBoard` у `delete_entity`) перечислены в `projects-vs-entities.md`.
