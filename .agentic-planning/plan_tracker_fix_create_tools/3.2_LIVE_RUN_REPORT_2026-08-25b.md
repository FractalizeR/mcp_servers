## D9: что подтверждено и что подтвердить нечем

Подтверждено: имя доски применяется (прежде молча возникала «Новая доска»), доска
адресуема по `/v3/boards/{id}` — на этом стояли пакеты 2.5 и 2.6, допущение снято.

**Не подтверждено:** применилась ли привязка к очереди через `autoFilters`. Прочитать
её нечем: `GET /v3/liveBoards/{id}` не существует (404), а `GET /v3/boards/{id}` поля
фильтра не отдаёт вовсе. Форма тела взята из документации; отрицательного сигнала нет,
но и положительного независимого чтения тоже. Записано как открытый вопрос, а не как успех.

Побочно подтверждено, что тело больше не игнорируется: первый вызов с
`sprintsAvailable` без `backlogAvailable` получил осмысленный отказ API
(`422 Работа по спринтам возможна только в очередях с настроенным бэклогом`) —
на устаревшем маршруте такой запрос молча создавал доску по умолчанию.

## D10: форма запроса верна, создание не проходит

Пять попыток, все отклонены, **ни одного поля не создано** (проверено `get_global_field`
по каждому идентификатору — везде 404).

Что установлено:

1. Короткая форма типа (`StringFieldType`, как в документации) — `400 type: Incorrect
   data format`. Значит **полная форма** (`ru.yandex.startrek.core.fields.StringFieldType`),
   выбранная пакетом 2.4, верна. Открытое допущение снято.
2. Полная форма — `500` с неопределённым исходом, воспроизводится на трёх разных
   категориях и на латинице в обоих языках имени. От содержимого тела не зависит.
3. **Контрольный опыт:** то же тело (та же категория, та же полная форма типа,
   локализованное имя) на `create_queue_local_field` в `TESTTEST` — **успех**,
   поле `6a8dbde7562fe96fb780ed9a--liveProbeLocal` создано.

Вывод: форма запроса глобального поля исправлена верно, а `500` приходит на стороне API
именно для создания поля уровня организации. Гипотеза (не доказана): административное
право, отданное как `500` вместо `403`. Дефектом инструмента это не является, но и
закрытым D10 считать нельзя.

Повтор POST инструмент не делал осознанно — сообщение об ошибке прямо требует сначала
проверить состояние ресурса. Проверка показала, что дублей не возникло.

## Не проверено и почему

- `update_global_field` — подозрение на шестой дефект того же рода (документация правки
  называет `name: {en, ru}`, наша схема правки шлёт строку). Проверить нечем: поля,
  на котором можно испытать правку, не появилось (см. D10).
- **Инструменты удаления сущностей организации** (`delete_global_field`, `delete_project`,
  `delete_board`) — по решению пользователя от 2026-08-26 прогон ничего не удаляет.
  Правило «сначала проверь удаление» здесь неприменимо осознанно.

## Рубеж области действия

Отказов рубежа за прогон нет: все запросы прогона легальны, префикс во всех именах,
ссылки на людей только на владельца прогона. Журнал сошёлся с созданным построчно,
включая обе формы адресации проекта (`72` и ключ) и локального поля
(составной id и короткий ключ).
