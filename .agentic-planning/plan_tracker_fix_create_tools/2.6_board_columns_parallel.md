# 2.6 — D11: неоднозначная адресация колонки доски (параллельно)

`id` колонки не уникален внутри доски: на доске с колонками `1,2,3` создание дало
четвёртую, тоже с `id: 1`. Дальше `update_board_column` по `columnId: 1` изменил чужую
колонку, а `delete_board_column` удалил **обе** колонки с этим id. На боевой доске это
молча портит чужое.

Решение пользователя: **отказывать при неоднозначной адресации**. Инструментов удаления
колонок это решение не отменяет — они существуют и остаются.

## Зависимость от 2.5

Пакет стоит на том, что доска, созданная через `liveBoards`, адресуется по
`/v3/boards/{id}` — иначе ни колонки читать, ни живьём проверять нечем. Подтверждение —
первый шаг живого прогона на 3.1; до него пакет пишется и проверяется на моках.

## Набор файлов

- `src/tracker_api/api_operations/board-column/{update,delete}-board-column.operation.ts`
- `src/tools/api/boards/{update,delete}-board-column.{schema,tool,metadata}.ts`
- `src/tools/api/boards/create-board-column.{tool,metadata}.ts` (только предупреждение)
- соответствующие тесты, `tests/helpers/board-columns.fixture.ts`

## Изменения контракта

- перед правкой и перед удалением колонки инструмент читает `GET /v3/boards/{id}/columns`
  и считает колонки с запрошенным `columnId`. Больше одной — **отказ** с перечислением
  имён колонок-претендентов и объяснением, что адресовать нечем; ни одной — отказ
  «колонки нет»; ровно одна — обычный ход;
- `create_board_column` после создания сообщает в `warnings`, если на доске появилась
  вторая колонка с тем же `id`: созданная колонка станет неадресуемой, и знать об этом
  надо сразу, а не при следующей правке;
- лишний GET на каждую правку — осознанная цена: альтернатива уже испортила чужую
  колонку на боевой доске.

## Definition of Done

- тесты на все три исхода проверки (нет / одна / несколько), включая текст отказа;
- тест на предупреждение при создании колонки-дубликата;
- `npm run validate:quiet` зелёный.

На 3.1 проверяется живьём на доске прогона: две колонки с одинаковым `id`, затем
попытка правки и удаления — обе обязаны отказать.
