# План: починка пяти инструментов создания (D1, D7–D11)

Основание — `../plan_tracker_test_coverage/5.2_LIVE_RUN_REPORT_2026-08-25.md`.
Пять инструментов создания не работали никогда; моки отвечали предписанным, поэтому
дефект был невидим. Отсюда главное правило плана: **пакет считается закрытым только
после вызова по боевому API**, зелёный юнит-тест закрытием не является.

- `0_CONTRACTS.md` — целевые формы запросов, снятые по документации Трекера.
- `enumeration.md` — перечисление артефактов, затронутых сменой маршрутов
  (чем снято и чего способ не видит — в шапке файла).

Этап 1.1 идёт первым, потому что без него живой прогон отклоняется рубежом на новых
маршрутах (`POST /v3/components`, `POST /v3/liveBoards`) — fail-closed по построению.
Этап 1.2 идёт вторым, потому что снимает единственное настоящее пересечение волны 2.x:
`tests/tracker_api/facade/yandex-tracker.facade.test.ts` и
`tests/integration/helpers/mock-server.ts` общие для нескольких пакетов, и параллельные
агенты затирали бы там работу друг друга.

**Живой прогон не параллелится.** Токен один и бьёт в боевой сервис; два агента с
`--dangerously-allow-write` мешают друг другу (`CLAUDE.md` §mcp-dev). Поэтому пакеты
2.x заканчиваются моками и юнит-тестами, а единственный живой прогон ведёт оркестратор
на этапе 3.1. Инструмент, не прошедший живьём, возвращается в свой пакет.
