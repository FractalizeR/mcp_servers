# 2.3 — D8: проект (параллельно)

`key` обязателен в нашей схеме и отвергается API в любой форме — параметра `key` у
`POST /v3/projects` нет вовсе.

- `src/tracker_api/dto/project/{update-project.dto.ts,dto.factories.ts}` — фабрики

- `src/tracker_api/facade/services/project.service.ts` (если понадобится)
- соответствующие тесты, `tests/helpers/project.fixture.ts`

## Изменения контракта (ломающие)

- `key` уходит из схемы и из DTO создания;
- `queueIds: string[]` → `queues: string` (ключ одной очереди), **обязательное** поле;
- `teamUserIds` уходит из создания: параметра нет в API;
- `status` принимает `DRAFT|IN_PROGRESS|LAUNCHED|POSTPONED`. Текущий enum —
  строчные `draft|in_progress|launched|postponed|at_risk`. Пакет обязан **проверить по
  ответу API**, в какой форме статус приходит, и привести схему к принимаемой; `at_risk`
  в перечне документации отсутствует — если API его не принимает, он уходит;
- `lead` перестаёт быть обязательным (в API он опционален);
- выход инструмента **не переименовывается**: `projectKey` отдают одинаково и
  `create_project`, и `update_project`, и `get_project`, а храповик контрактов
  (`scripts/check-tool-contract-ratchet.ts`) как раз сводил семейства к единому имени.
  Менять имя выхода в одном инструменте из трёх — вернуть разнобой. Если ключ, назначенный
  сервером, окажется бесполезен, это отдельная задача на всё семейство.

`base-project.schema.ts` общий с `update_project`, и наборы полей у создания и правки
теперь разные: в общей базе остаётся только действительно общее, остальное разъезжается
по двум схемам. Рубеж уже разведён так же (этап 1.1, раздельные перечни ключей), поэтому
правка проекта обязана продолжать слать `queueIds`/`teamUserIds` — либо пакет называет
расхождение в отчёте, и перечни правит оркестратор.

## Definition of Done

- вызов без `key` проходит валидацию, вызов с `key` отвергается схемой;
- `update_project` остаётся рабочим — его интеграционные тесты зелёные;
- если состав тела `PATCH /v3/projects/{id}` изменился, пакет называет новый перечень
  ключей в отчёте: этап 1.1 брал его из текущего `UpdateProjectDto`, и расхождение
  правится оркестратором на этапе 3.1;
- `npm run validate:quiet` зелёный.
