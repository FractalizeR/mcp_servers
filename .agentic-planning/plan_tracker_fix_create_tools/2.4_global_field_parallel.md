# 2.4 — D10: глобальное поле (параллельно)

`{name, schema:{type}}` → `400 schema: Incorrect data format`. Ключа `schema` в запросе
нет: он приходит только в ответе. Форма создания совпадает с уже работающим
`create_queue_local_field`.

## Набор файлов

- `src/tracker_api/api_operations/field/create-field.operation.ts`
- `src/tracker_api/dto/field/create-field.dto.ts`
- `src/tools/api/fields/{create-global-field,field-value}.schema.ts`,
  `create-global-field.{tool,metadata}.ts`
- `src/tracker_api/facade/services/field.service.ts` (если понадобится)
- соответствующие тесты, `tests/helpers/global-fields.fixture.ts`

## Изменения контракта (ломающие)

Тело `POST /v3/fields`:

| Ключ | Обяз. | Замечание |
|---|---|---|
| `id` | да | короткий идентификатор поля, нового параметра в схеме не было |
| `name` | да | **объект** `{en, ru}`, а не строка |
| `category` | да | id из `GET /v3/fields/categories` (живо проверено: маршрут доступен) |
| `type` | да | у локального поля работает полная форма `ru.yandex.startrek.core.fields.StringFieldType` |
| `order`, `description`, `readonly`, `visible`, `hidden`, `container`, `optionsProvider` | нет | |

- `schema` уходит из тела запроса; `FieldSchemaValueSchema` остаётся только там, где
  описывает **ответ**, и если больше нигде не нужна — удаляется;
- `options` и `suggest` из тела создания уходят — развилка закрыта в `0_CONTRACTS.md`,
  и рубеж ограничен тем же перечнем: расхождение дало бы отказ рубежа вместо ошибки API;
- `type` пакет обязан проверить в **обеих** формах (короткой `StringFieldType` и полной);
  в схему идёт та, что принята API, а описание параметра называет допустимые значения.

`update_global_field` (`PATCH /v3/fields/{id}`) в этот пакет входит только перечнем
своих ключей: он рабочим не признан и не ломается — его тело не меняется.

## Definition of Done

- юнит-тест операции сверяет тело целиком; в теле нет ключа `schema`;
- схема отвергает вызов без `id`/`category`/`type` и вызов со строковым `name`;
- моки отвечают на новую форму; старая форма в моках отсутствует;
- `npm run validate:quiet` зелёный.

Живая проверка на 3.1 заканчивается чтением созданного поля, а **не** его удалением:
удаление боевых сущностей организации оставлено пользователю (решение 2026-08-26).
Значит, `delete_global_field` остаётся непроверенным живьём — это фиксируется в отчёте
прогона, а не считается закрытым.
