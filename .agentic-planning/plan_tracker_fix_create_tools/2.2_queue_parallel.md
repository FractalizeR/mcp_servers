# 2.2 — D7: очередь (параллельно)

`create_queue` невозможно вызвать: API требует `issueTypesConfig`, схема такого поля
не знает, а неизвестные ключи схема отклоняет.

## Набор файлов

- `src/tracker_api/api_operations/queue/create-queue.operation.ts`
- `src/tracker_api/dto/queue/create-queue.dto.ts`
- `src/tools/api/queues/create-queue.{schema,tool,metadata}.ts`
- `src/tracker_api/dto/queue/dto.factories.ts` — собирает `CreateQueueDto` и без
  обязательного `issueTypesConfig` перестанет компилироваться
- `src/tracker_api/facade/services/queue.service.ts` (если понадобится)
- соответствующие тесты

## Изменения контракта

- добавляется **обязательный** `issueTypesConfig: [{issueType, workflow, resolutions[]}]`.
  Обязательный, а не «с умолчанием»: `workflow` — идентификатор из справочника
  организации, и угаданный пресет молча создал бы очередь с чужим рабочим процессом;
- описание инструмента называет, откуда берутся значения: `raw_api_request GET
  /v3/workflows`, `get_issue_types`, `get_resolutions`. Живо проверено, что первый
  маршрут доступен и отдаёт как пресеты, так и рабочие процессы организации;
- `name` ограничивается 40 символами в схеме — предел найден живым прогоном и сейчас
  проявляется как `422` уже после отправки;
- `key`: регулярное выражение `^[A-Z]{2,10}$` живой прогон не оспорил — остаётся.

## Definition of Done

- схема отвергает вызов без `issueTypesConfig` и с именем длиннее 40;
- юнит-тест операции сверяет тело запроса целиком, включая `issueTypesConfig`;
- сообщение об ошибке валидации называет способ добыть `workflow`;
- `npm run validate:quiet` зелёный.
