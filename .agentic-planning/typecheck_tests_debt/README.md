Итог: **0 во всех пакетах**, где есть `tsconfig.tests.json`. Гейт включён и проверен делом.

## Почему исправленных мест меньше, чем 938 ошибок

Ошибки шли каскадами от небольшого числа причин; часть отваливалась сама после
уточнения типа в одном месте. Основные группы:

| Причина | Мест правки | Снято ошибок |
|---|---:|---:|
| `content[0]?.text` у union-блока (`{}` вместо строки) | 315 обращений в 54 файлах | 931 → 616 |
| Индексный доступ без проверки (`items[0].field`) | 195 обращений + 23 блока `if` | 616 → 364 |
| `BatchResult` без обязательного `index` | 86 литералов | часть 364 → 206 |
| `Issue.queue` — усечённый объект вместо `Queue` | 35 литералов | там же |
| Доступ к полю из индексной сигнатуры (`TS4111`) | 40 обращений | там же |
| Прочее (контракты DTO, фикстуры, axios, protected) | ~90 мест | 206 → 0 |

Разница между 938 и суммой правок объясняется тем, что `tsc` показывает не все
элементы массива при несовпадении (сообщает по первому), и тем, что одна правка
типа фикстуры снимала до десятка ошибок в разных файлах.

| Пакет | `!` до → после | `as X` до → после |

Добавлено ровно одно приведение — в `delete-checklist-item.operation.test.ts`, где
`deleteRequest` объявлен `protected` и структурно выразить его снаружи нельзя; оно
стоит за рантайм-проверкой наличия метода.

## Что гейт не покрывает

`packages/framework/*` не имеют `tsconfig.tests.json`, а их `tsconfig.json` включает
только `src/**/*` — тесты framework типами не проверяются. Замер пробным конфигом
(2026-08-19): **infrastructure 8, cli 0, core 149**. Это отдельный объём, в этот пакет
работ не входил.
