исправленные и новые инструменты должны сразу рождаться с `outputSchema` и annotations, иначе их
придётся переделывать дважды. Сквозные инфраструктурные дефекты, найденные тем же аудитом (повтор
неидемпотентных POST, потеря `errorsData`), подняты в этап 1 — они не про конкретный сервер.

Этапы 3 и 4 не зависят друг от друга и могут идти параллельно: наборы файлов не пересекаются
(3 — `definition/`, `tools/`; 4 — `server.ts`, transport-adapter). Оба зависят от 2, потому что
удаление lazy сокращает поверхность, которую иначе пришлось бы переносить дважды.

`main`.

## Найденное по ходу, не входящее ни в один этап

- **Документация сервера Вики отстала от кода.** Её `README.md` перечисляет 7 инструментов страниц и
  `ping`, тогда как 12 инструментов таблиц, ресурсов и raw API существовали ещё до этого плана;
  `CLAUDE.md` сервера утверждает, что «Фаза 2: Grids & Resources (не начата)», хотя она давно
  закончена. Найдено пакетом 3.1.C.wiki, им же не исправлено намеренно: обновление документации
  сервера — отдельная работа, а не довесок к простановке annotations. Заводится отдельной задачей
  после плана.

**Инвентарь протухает.** Перед стартом каждого этапа перечисление пересобирается заново по актуальному
коду — унаследованная таблица выглядит как выполненная работа, но собиралась под другой вопрос.

## Общие правила исполнения

- Рабочее дерево для каждого пакета указывается явно в его разделе. По умолчанию — основной чекаут при
  strict file isolation; worktree там, где пакеты пишут параллельно в пересекающиеся области.
- Агентам запрещены `git stash`, `git checkout -- <file>`, `git restore`, `git clean` в общем дереве.
- После каждого этапа: `npm run validate:quiet`, отметка прогресса здесь, коммит на русском.
- Ветка `main` защищена — перед коммитом в неё спрашивать.
