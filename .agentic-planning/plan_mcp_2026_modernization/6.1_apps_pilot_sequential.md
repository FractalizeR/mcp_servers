# Этап 6. Пилот MCP Apps (sequential)

Зависит от этапа 5: App — это ресурс `ui://`, на который инструмент ссылается через
`_meta.ui.resourceUri`, а данные приходят из результата вызова. Раньше Resources и `structuredContent`
это технически невозможно.

Рабочее дерево: **worktree** — пилот тянет свою сборку фронтенда, которой в основном дереве нет.

## Ограничение, определяющее дизайн

MCP Apps поддерживают Claude, Claude Desktop, VS Code Copilot, M365 Copilot, Goose, Postman.
**ChatGPT и Codex — нет.** Половина команды пилот не увидит, поэтому **tool-fallback обязателен**:
любой сценарий должен полностью работать без UI, а App — быть надстройкой, а не единственным путём.

## Пилот №1 — анализ задачи и правка description

**Почему именно он.** Единственный из рассмотренных сценариев, где есть человеческий ввод, а не
только отображение. Правка текста через диалог — это три круга «нет, вот здесь не так»; виджет с
редактируемым полем убирает их. Ценность видна нетехническому пользователю, что и нужно для вовлечения
команды.

**Механика.**
1. Инструмент анализа задачи возвращает результат, в описании которого объявлен `ui://` ресурс.
2. Хост подгружает ресурс и рендерит его в песочном iframe.
3. App показывает текущее описание и предложение модели рядом.
4. Продакт правит текст прямо в поле и подтверждает.
5. App вызывает инструмент обновления задачи сам, через postMessage-канал к хосту.

**Требования безопасности.**
- Содержимое описания приходит из Трекера и для рендера **недоверенное**: виджет вставляет его
  только через `textContent`/`.value`, `innerHTML` не используется.
  ⚠️ Правка от 2026-08-28: требование «санитайз обязателен» снято. Санитайзер вырезал из текста
  всё похожее на HTML-тег и тем самым уничтожал разметку YFM (`<{cut}>`, `<#html#>`) и обычные
  сравнения (`latency < 200`), а этот же текст виджет пишет обратно в задачу через `update_issue`
  — то есть «защита» молча портила данные в Трекере. Чистка на границе данных несовместима с
  путём записи; безопасность рендера обеспечивается способом вставки.
- CSP объявляется в `_meta.ui.csp`; без крайней необходимости внешние origin не разрешаем.
- Всё бандлится в сам ресурс: внешние скрипты и шрифты не подключаем.

**Fallback.** Без Apps инструмент возвращает обычный текст с предложением, и правка идёт диалогом,
как сейчас.

## Пилот №2 — динамический список поиска с массовыми действиями

Делается после первого и только если первый себя оправдал.

**Почему он ценен.** Выигрыш не в удобстве, а в контексте: найденные задачи не попадают в контекст
модели вообще. Пользователь фильтрует и листает внутри виджета — курсорная пагинация уже есть, App
дозагружает страницы сам, — отмечает нужные, и наружу уходит только выбранное.

Сюда же поглощается сценарий «перевод статуса»: отдельным приложением он смысла не имеет, потому что
одиночный переход агент делает текстом не хуже. Внутри списка у него появляется то, чего текст не
умеет: в Трекере доступны не произвольные статусы, а конкретные переходы из текущего, и виджет
показывает реальные transitions вместо угадывания моделью.

**Fallback.** Без Apps — существующие инструменты поиска и массовых операций.

## Что в пилот не входит

**Preview страницы Вики.** Потребовал бы рендерер Yandex Flavored Markdown внутри iframe, который
всегда будет отставать от настоящего рендера Вики, ради результата, достижимого ссылкой на страницу.
Полезная часть сценария — diff перед сохранением — вынесена в этап 3 (пакет 3.1.E) как обычный
инструмент: так она работает во всех клиентах, включая Codex, и стоит несопоставимо дешевле.

## DoD этапа

- Пилот №1 работает в Claude Desktop: анализ, правка, применение изменения.
- Тот же сценарий полностью проходится без Apps — в Codex CLI.
- Описание доезжает до виджета и обратно побайтово; тест с описанием, содержащим разметку и
  скрипт, доказывает, что разметка не становится узлами DOM и не теряется по дороге.
- JS виджета исполняется в тесте (jsdom + фальшивый хост): хендшейк, ответы на запросы хоста,
  имя вызываемого инструмента сверено с реестром сервера.
- Размер бандла ресурса зафиксирован порогом в тесте.
- `npm run validate:quiet` зелёный.

## Риски

- Apps — расширение, а не ядро; поддержка хостов будет меняться. Не строить на нём ничего, без чего
  нельзя обойтись.
- Соблазн отдать в App больше данных, чем нужно для отображения. Всё, что уходит в iframe, — это
  данные, покинувшие контроль сервера.
