## Найдено сверх §7

**`update_sprint` не работает вовсе.** Без `version` API отвечает `428`
(«укажите либо параметр 'версия', либо заголовок If-Match»), с `version` в теле —
`400 version: Incorrect data format`. Операция кладёт версию в тело
(`update-sprint.operation.ts`). Тот же класс, что закрытые `update_component`
и `update_project`.

**`manage_queue_access` неверен целиком**, а не в одном ключе. Документация
`api-ref/queues/manage-access` (раздел запроса) объявляет тело
`{ <разрешение>: { users|groups|roles: [...] | { add|remove: [...] } } }`, где
разрешение ∈ `create`, `write`, `read`, `grant`, `deny`. Наш инструмент шлёт
`{ <роль>: { <действие>: [субъекты] } }` — ни одна из четырёх «ролей» разрешением не
является. Форма ответа тоже разошлась: API отдаёт объект, ключёванный разрешением,
а `QueuePermissionsOutput` объявлен массивом.

**Ложная тревога, снята проверкой:** `create_board.queue` доезжает — очередь видна в
`autoFilterSettings.addFilterSettings.liveFilter`, просто не возвращается полем
`filter` в ответе создания.

**Подтверждение метода сверки.** `startDateTime` — образцовый случай, ради которого
поиск сузили до раздела запроса: имя есть в примере ответа и его нет в разделе
запроса, и API его действительно не принимает.

## Класс «версия обязательна» — где ещё искали

Дефект `update_sprint` — тот же класс, что закрытые `update_component` и
`update_project`, поэтому остальные операции правки проверены отдельно.

| Операция | Как шлёт версию | Исход |
|---|---|---|
| `update_component` | `?version=`, дочитывает | работает (починено 2026-08-25) |
| `update_issue`, `update_entity` | `?version=`, необязательна | работает |
| `update_queue`, `update_board`, `update_board_column`, `update_worklog` | не шлёт | работают без версии (живые пробы 25 и 26 августа) |
| `update_queue_local_field` | не шлёт | **работает без версии** — локальное поле `sweep7Local` очереди `TEST`, версия 1→2, чтение подтверждает |
| `update_filter` | не шлёт | **работает без версии** — фильтр `7` переименован, прямое чтение `GET /v3/filters/7` подтверждает |
| `update_global_field` | не шлёт | не проверить (D10) — открытый пункт §1 соседнего плана |
| `update_sprint` | телом | **сломан**: без версии `428`, версия телом `400` |
| `manage_sprint_lifecycle` (`start`, `archive`) | не шлёт и параметра не имеет | **сломаны**: `428` на спринтах `236` и `237` |
| `manage_sprint_lifecycle` (`delete`) | не шлёт | работает — спринт `237` удалён |

То есть класс не системный, но и не единичный: носитель — предмет «спринт» целиком.
`DELETE /v3/sprints/{id}` версии не требует, а `POST .../_start` и `POST .../_archive` —
требуют, и параметра `version` у `manage_sprint_lifecycle` нет вовсе. Починка B обязана
покрыть оба инструмента, иначе половина предмета останется сломанной.

## Форма ответа `PATCH .../permissions` — снята живьём

`PATCH` отвечает **только** `{ self, version }`, без единого разрешения. Полную форму
(`{ self, version, create, write, read, grant }`, внутри — `{ self, users, groups, roles }`)
отдаёт `GET` того же ресурса; она сохранена в
`inventory/queue-permissions-response-2026-08-26.json`.

Это оправдало разбиение пакета C надвое: типизация «по документации» объявила бы
разрешения обязательными, и инструмент падал бы на каждом успешном `PATCH`. Совпало и с
референсным клиентом, чей смоук мокает ответ как `{"version": 11}`.
Ключ `deny` не наблюдался ни разу — в типе он необязателен и помечен непроверенным.

## Открыто: `permission: 'read'` не даёт эффекта

На очереди `TESTSWEEPB` мутация чтения принимается с 200 и не делает ничего — проверено
дважды, с чтением состояния до и после:

- `read` + `users` + `add ['vr']` — `read.users` остался пуст, версия не изменилась;
- `read` + `roles` + `add ['author']` — `read.roles` остался `['access']`, версия не изменилась.

Соседние разрешения на той же очереди в том же прогоне работают (`write`, `grant`), то
есть дело не в теле запроса и не в правах токена. Причина не установлена: вероятнее
всего, очередь открыта на чтение («Все сотрудники» имеют `create`/`write`), и
индивидуальные права чтения в ней бессмысленны.

**Это наблюдение об API, а не дефект инструмента** — тело мы шлём документированное.
Закроет: проба на очереди с ограниченным доступом.
