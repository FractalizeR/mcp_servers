## Цель
Единый компонент, который:
1. Парсит заголовок `Link` (RFC 5988): извлекает URL для `rel="next"` и шаблон для `rel="seek"`.
2. Парсит `X-Total-Count` / `X-Total-Pages` (seek).
3. Реализует `fetchAll` — проход по `next` до исчерпания или до лимита.
4. Строит `PaginationMeta` для одиночной страницы.

## Контракты (сигнатуры, без реализации)
- `parseLinkHeader(headerValue?: string): { next?: string; seek?: string }`
- `stripHost(url: string): string` — превратить абсолютный next-URL в относительный путь+query (аналог Python `_strip_host`).
- `buildMeta(args): PaginationMeta` — собрать метаданные из заголовков/состояния.
- `fetchAllPages<T>(opts): Promise<PaginatedResult<T>>`, где `opts`:
  - `firstResponse: HttpResponseEnvelope<T[]>` — уже полученная первая страница;
  - `requestNext: (path: string) => Promise<HttpResponseEnvelope<T[]>>` — как запросить следующую (тот же метод/тело; для GET — `getWithResponse`, для POST `_search` — `postWithResponse` с тем же телом);
  - `maxItems: number` (дефолт 500), `maxPages?: number` (backstop, напр. 100).

## Ключевая логика (псевдокод)
```
items = firstPage; pages = 1
next = parseLinkHeader(headers.link).next
while next && items.length < maxItems && pages < maxPages:
    resp = requestNext(stripHost(next))
    items.push(...resp.data); pages++
    next = parseLinkHeader(resp.headers.link).next
truncated = Boolean(next) && items.length >= maxItems   // ещё есть, но обрезали
if items.length > maxItems: items = items.slice(0, maxItems); truncated = true
// ... build PaginationMeta: hasNextPage = Boolean(next) || truncated, fetchedAll=true
```

## Edge cases
- Нет `Link` → одна страница, `hasNextPage=false`, `fetchedAll` зависит от запроса.
- `next` указывает на абсолютный URL с хостом → `stripHost`.
- Зацикливание (сервер всегда отдаёт next) → backstop `maxPages` + флаг `truncated`.
- Усечение последней страницы до `maxItems` (см. DP-4).
- seek без `X-Total-*` (чистый cursor) → `total/totalPages` не заполняем.
- POST `_search`: `requestNext` обязан переотправлять то же тело (иначе next вернёт не то).

## Тест-план
- Парсинг `Link` с одним/несколькими rel, с/без `seek`, с кавычками и пробелами.
- `stripHost` для абсолютного и относительного URL.
- `fetchAllPages`: 1 страница; N страниц; упор в `maxItems` (truncated=true, ровно maxItems записей); упор в `maxPages`; пустой ответ.
- `buildMeta`: с `X-Total-*` и без.
