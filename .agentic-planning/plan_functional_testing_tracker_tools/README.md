# План функционального тестирования MCP-инструментов Яндекс.Трекера

**Вопрос, на который план отвечает:** что нужно проверить, чтобы утверждать «все 92 инструмента
работают как надо» — и чем именно это проверяется, чтобы утверждение было проверяемым, а не декларацией.

Инвентарь инструментов (основание всех обобщений в плане): [0_inventory_tools.md](0_inventory_tools.md).

---

## 1-2. Что считаем «работает как надо» и чем это проверяется

Вынесено в постоянный канон:
[packages/servers/TESTING_STRATEGY.md](../../packages/servers/TESTING_STRATEGY.md) — семь свойств
С-1..С-7, уровни проверки, инвариант проверки эффекта, правила живых прогонов (канон всех серверов);
[packages/servers/yandex-tracker/tests/TESTING_STRATEGY.md](../../packages/servers/yandex-tracker/tests/TESTING_STRATEGY.md)
— специфика Трекера.
Этапы ниже ссылаются на эти обозначения и не повторяют их.

Этот план — транзиентный: после исполнения удаляется, канон остаётся.

## 3. Приоритеты (риск = цена ошибки × вероятность)

1. **P0 — мутирующие инструменты без живой проверки.** 52 инструмента с `readOnlyHint=false`,
   из них 14 деструктивных. Ошибка здесь портит данные пользователя необратимо.
2. **P0 — bulk-операции.** `bulk_update_issues`, `bulk_transition_issues`, `bulk_move_issues`,
   `get_bulk_change_status`: у трёх из них **нет ни unit-, ни интеграционного теста**, при этом
   каждая правит произвольное множество задач разом.
3. **P0 — область действия живых прогонов.** Отдельной организации нет, песочница — очередь `TEST`
   в боевой. Изоляция правами недоступна, поэтому ограничение области действия перенесено в оснастку
   и само становится предметом тестирования (этап 1.1).
4. **P1 — пагинация и batch-частичные отказы.** Класс дефектов уже реализовывался дважды.
5. **P1 — 59 инструментов без интеграционного теста**, в первую очередь целые непокрытые категории:
   BOARDS (9), PROJECTS/entities/goals (14), SPRINTS (5), fields/filters/worklog.
6. **P2 — discoverability и размер ответов** (С-7).

## 5. Общий DoD плана

- `npm run validate:quiet` зелёный в каждой ветке этапа;
- ни один инструмент из инвентаря не остался без строки в матрице «инструмент × свойство С-1..С-7»
  со значением «покрыт тестом X» либо «сознательно не покрывается, причина»;
- живой прогон 3.1 выполнен и его отчёт зафиксирован файлом с перечнем расхождений;
- каждое найденное расхождение либо исправлено с регрессионным тестом, либо заведено задачей.
