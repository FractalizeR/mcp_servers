# Этап 3.1 — Приёмка против живого Трекера (sequential)

Свойства С-4 (верность API) и С-5 (правдивость эффекта). **Единственный уровень, который их проверяет.**
Мок подтверждает лишь то, что автор кода и автор мока поняли API одинаково — включая случай,
когда оба поняли неверно.

Требует этапа 1.1 (песочница + harness). Прогон одиночный: параллельные прогоны в одной очереди
портят друг другу выборки.

**Песочница — очередь `TEST` в боевой организации** (отдельной тестовой организации нет). Отсюда два
следствия для этого этапа: (а) все выборки фильтруются по префиксу прогона, потому что в очереди
лежат чужие задачи; (б) сценарии из реестра исключений 1.1 (очереди, глобальные поля, доступы,
проекты) живьём не гоняются — по ним остаётся только моковый уровень, и это осознанная непокрытая
зона, а не забытая.

## Инвариант проверки эффекта
Результат мутирующего инструмента **никогда не принимается как доказательство**. После каждой мутации —
`readBack` через `raw_api_request` и сравнение с ожидаемым состоянием. Инструмент, который отчитался
об успехе, ничего не изменив, — исторически реальный класс дефекта в этом проекте.

## Сценарии

**Ж-1. Жизненный цикл задачи.** create → get → update (все типы полей: текст, дата, пользователь,
список, локальное поле) → transitions → transition → changelog. Проверить: изменённые поля видны при
независимом чтении; changelog содержит ровно сделанные изменения; `transition_issue` возвращает
задачу, а не описание перехода (регрессия).

**Ж-2. Обвязка задачи.** комментарии (add/edit/get/delete), чеклисты, вложения (upload/get/download/
thumbnail/delete — включая бинарный файл и файл с кириллицей в имени), связи, worklog.
Для каждого delete — подтвердить исчезновение независимым чтением.

**Ж-3. Поиск и пагинация вживую.** Создать в песочнице заведомо больше сущностей, чем `perPage`
(и по каждому типу постранички: offset, курсор, `Link`), затем:
- собрать все страницы и сверить множество ключей с созданным — ни потерь, ни дублей;
- на последней странице `hasNextPage=false`;
- `find_issues` в режимах `links` и `full` возвращает одно и то же множество ключей.

**Ж-4. Bulk (P0).** Только по явному списку ключей задач, созданных этим прогоном — «все задачи
очереди» в общей организации запрещено оснасткой. `bulk_update_issues` / `bulk_transition_issues` /
`bulk_move_issues` на наборе, где часть задач заведомо непригодна (нет перехода, нет прав, несуществующий ключ):
- изменения применились ровно к пригодным — проверено независимым чтением каждой задачи набора;
- непригодные попали в `failed` с причиной;
- `get_bulk_change_status` доводит асинхронную операцию до финального состояния и не зависает.

**Ж-5. Структуры проекта.** очереди, компоненты, доски и колонки, спринты, проекты, сущности и
goal key results — создание, чтение, изменение, удаление в песочнице с read-back.

**Ж-6. Права и отказы.** Вызов инструмента на очередь вне песочницы ⇒ контрактная ошибка 403,
а не аварийное завершение. Заведомо несуществующий ключ ⇒ 404 в `failed`, остальной batch отработал.

**Ж-7. Идемпотентность.** Для инструментов с `idempotentHint=true` — повтор с теми же параметрами
не создаёт вторую сущность и не меняет состояние.

## DoD
- Отчёт прогона файлом: инструмент × сценарий × вердикт × расхождение.
- Каждый мутирующий инструмент, не попавший в реестр исключений (этап 1.1), имеет хотя бы один
  живой сценарий с read-back.
- Песочница после прогона пуста.
- Каждое расхождение либо исправлено с регрессионным тестом на моках (чтобы дефект не вернулся
  без живого прогона), либо заведено задачей с воспроизведением.

**Ж-8. Разведка недокументированных эндпоинтов.** Официальная документация описывает раздел фильтров
скудно — наш `get_filters` уже опирается не на неё, а на общий механизм референсного клиента
(см. комментарий в `get-filters.operation.ts`). Проверить живьём наличие `DELETE /v3/filters/{id}`:
создать фильтр прогона, попытаться удалить, зафиксировать код ответа. Результат — основание либо
завести `delete_filter` и закрыть асимметрию CRUD, либо записать в документацию, что метода нет.
Тот же приём применить к прочим местам, где endpoint выведен из механики SDK, а не из документации.
