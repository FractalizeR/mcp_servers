# Этап 2.2 — Сквозное поведение на краях (parallel)

Свойство С-6. Мок-уровень: здесь проверяется наша логика вокруг ответов API, а не сам API.

## П-1. Пагинация (20 операций используют `TrackerPaginator`)
Для каждого пагинируемого эндпоинта, по типам постранички отдельно (offset/`page`, курсор,
`Link rel="next"`, `truncated`):
- полная страница ⇒ `hasNextPage=true`; неполная ⇒ `false` (регрессия ложного `hasNextPage`);
- последняя страница пустая ⇒ обход завершается, а не зацикливается;
- курсорные эндпоинты: `nextCursor` выдан ⊇ `hasNextPage`; курсор из ответа принимается следующим вызовом;
- `perPage` не задан ⇒ дефолт не превращает `count:1` в «есть ещё»;
- защитный лимит числа страниц: обрыв помечается отдельно от «есть ещё данные» (разный смысл).

## П-2. Batch и частичные отказы
- смешанный исход (часть задач 200, часть 404/403) ⇒ обе группы заполнены, исключение не летит;
- все упали ⇒ по-прежнему структура результата, а не throw;
- `MAX_CONCURRENT_REQUESTS` соблюдается: одновременных запросов не больше лимита
  (проверять барьером, а не таймингами — тайминговый вариант уже давал флак);
- `MAX_BATCH_SIZE` превышен ⇒ понятный отказ на валидации, а не частичное выполнение;
- порядок элементов в `successful`/`failed` не зависит от порядка завершения запросов.

## П-3. Отображение ошибок API
Для каждого класса ответа — 400, 401, 403, 404, 409, 412, 422, 429, 500, 502, таймаут, обрыв
соединения — единый контракт ошибки инструмента: машиночитаемый код + текст, без утечки токена
и без сырого стектрейса. Проверить, что 429 и 5xx уходят в ретрай, а 4xx — нет
(`RETRY_ATTEMPTS`/`RETRY_MIN_DELAY`/`RETRY_MAX_DELAY`).

## П-4. Данные
- кириллица и эмодзи в `summary`/`description`/комментариях проходят туда и обратно без порчи;
- многострочный текст и markdown не схлопываются;
- очень длинное поле — поведение определено (обрезка либо ошибка), а не «как получится»;
- даты/таймзоны: worklog и дедлайны не сдвигаются на границе суток.

## П-5. Редакция секретов
Токен и заголовки авторизации не попадают в логи ни на одном уровне (`LOG_LEVEL=trace`) —
расширить `tests/smoke/tool-redaction-allowlist.smoke.test.ts` на весь инвентарь.
