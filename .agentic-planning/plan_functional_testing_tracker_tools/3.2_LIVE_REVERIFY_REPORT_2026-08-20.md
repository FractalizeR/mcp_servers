## Дополнительные сценарии из ревью плана

- **Режим `links` у `find_issues`** — предупреждений не даёт. Это тот случай, где наивная
  реализация выдала бы `FIELDS_WITHOUT_VALUE` на весь список `fields` при полностью корректном
  вызове: тела сущностей заменены на `resource_link`, ни одно поле в ответе не присутствует.
- **Вызов без промахов по полям** — ключа `warnings` в ответе нет (инвариант «только когда непусто»).
- **Доступ по внутреннему id** — принимается, в том числе для вложенных ресурсов.

## Форма предупреждения

```
{ "code": "FIELDS_WITHOUT_VALUE",
  "message": "Поля из параметра fields не вернули значения ни у одного элемента ответа: totallyBogusFieldName",
  "details": { "fields": ["totallyBogusFieldName"] } }
```

Формулировка намеренно называет **наблюдаемый факт**, а не гипотезу о причине: отличить опечатку
от легитимно пустого поля по ответу API невозможно (README §2).
