# Пакет 2.4 — Корневая документация (parallel)

**Зависит от:** 1.2
**Параллелен:** 2.1–2.3
**Модель исполнителя:** младшая.

## Набор файлов

- `CLAUDE.md` (корневой)
- `DOCS.md`
- `ARCHITECTURE.md` (упоминание нового пакета в графе зависимостей)
- `packages/framework/dev-client/README.md`

## Что делаем

1. В корневой `CLAUDE.md` — **короткий** раздел (ориентир: 12–18 строк) о dev-интерфейсе:
   - зачем он существует: вызвать инструмент после доработки, не переподключая MCP к агенту;
   - три команды с примерами в одну строку;
   - правило после разработки: **прогнать через `mcp:batch` разумный набор кейсов по тому, что затрагивали** — затронутые инструменты, их граничные значения и хотя бы один ошибочный вход;
   - запись закрыта: `--dangerously-allow-write` ставится осознанно и разово;
   - предупреждение: вызовы идут в боевой сервис под реальным токеном.
2. В `DOCS.md` — строка навигации на README пакета.
3. В `ARCHITECTURE.md` — новый пакет в графе зависимостей framework.

## Definition of Done

1. `npm run validate:docs` проходит: корневой `CLAUDE.md` остаётся в лимите 400 строк.
2. Раздел отвечает на вопрос «что делать сразу после доработки инструмента» без перехода в другие файлы.
3. В README пакета есть формат JSONL и таблица кодов возврата.

## Уточнения редакции 2

- Команды в документации называются `tools:list` / `tools:call` / `tools:batch` (имя `mcp:*` занято другим смыслом).
- Формулировка про секреты — фактическая: вывод dev-интерфейса не проносит токен по неосторожности; от намеренного чтения агентом это не защищает.
- Добавить предупреждение: два агента в двух worktree с флагом записи работают с одним и тем же боевым сервисом.
- Добавить строку про свежесть: бандл пересобирается перед прогоном, устаревший бандл даёт отказ, а не молчаливый неверный результат.
