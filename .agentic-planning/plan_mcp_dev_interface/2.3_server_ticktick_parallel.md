# Пакет 2.3 — Скрипты и документация `ticktick` (parallel)

**Зависит от:** 1.2
**Параллелен:** остальным пакетам 2.x
**Модель исполнителя:** младшая.

## Набор файлов

- `packages/servers/ticktick/package.json` — **только секция `scripts`** (devDependency уже добавлена пакетом 1.2, `package-lock.json` не трогаем)
- `packages/servers/ticktick/CLAUDE.md`
- `packages/servers/ticktick/dev-calls.example.jsonl`

Файлы других серверов, framework-пакетов и корня — **не трогаем**.

## Что делаем

1. Добавить скрипты `tools:list`, `tools:call`, `tools:batch` с `--server-name fractalizer_mcp_ticktick` и `--package-dir .`.
   **Имя `mcp:list` не занимать** — оно уже означает «список MCP-клиентов и их статус».
2. Положить пример батча на 2–3 read-вызова (инструменты с префиксом `fr_ticktick_`).
3. Добавить в `CLAUDE.md` сервера короткий раздел: как прогнать затронутые кейсы после доработки, что запись закрыта флагом, что вызовы идут в боевой сервис.

## Definition of Done

1. `npm run tools:list` печатает список инструментов (ожидаемо 25) с классами read/write/local-side-effect.
2. `npm run tools:batch -- dev-calls.example.jsonl` проходит и печатает JSONL результатов.
3. Если сервер не подключён у исполнителя — DoD 1 и 2 считаются выполненными при получении **внятного** отказа `notConnected` (а не `unparsable` и не падения), и это отмечается в отчёте пакета.
4. `npm run validate:docs` проходит — лимит размера `CLAUDE.md` не превышен.
5. `npm run validate:quiet` в пакете проходит.
6. `package-lock.json` в диффе пакета отсутствует.

## Предусловие, специфичное для ticktick

На машине пользователя ticktick **не зарегистрирован** в `claude mcp` (проверено: `claude mcp list`
показывает только tracker и wiki), а в `packages/servers/ticktick/package.json` нет скриптов
`mcp:connect`/`mcp:status`, которые есть у двух других серверов, — то есть «сделать по образцу»
механически не срабатывает, образца нет.

Поэтому пакет дополнительно:

1. Добавляет недостающие `mcp:connect`, `mcp:disconnect`, `mcp:list`, `mcp:status` по образцу tracker и wiki (в том же наборе файлов — `package.json` сервера).
2. Фиксирует предусловие: перед проверкой DoD сервер подключается через `mcp-ticktick-connect`. Если подключение невозможно — работает ветка DoD 3.

Секреты ticktick (`TICKTICK_ACCESS_TOKEN`, `TICKTICK_REFRESH_TOKEN`, `TICKTICK_CLIENT_SECRET`)
читаются сервером из окружения — маскер обязан покрывать их независимо от того, пришли они из
записи клиента или из родительского окружения (требование пакета 1.1).
