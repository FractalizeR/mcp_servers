# Этап 3.4 (PARALLEL) — проекция полей оставляет пустые объекты

## Проблема
`ResponseFieldFilter` при запросе `fields.to.display` для элементов без `display`
(sla, boards в changelog) даёт `"to": [{}, {}, {}]` — мусор в контексте агента.

## Решение
Не создавать ключ, если после проекции вложенного пути не осталось ни одного поля.
Пустой массив/объект, пришедший из API как есть, при этом должен сохраняться — разница
между «API вернул пусто» и «проекция ничего не отобрала» обязана быть в тестах.

## Риск
Утилита общая для framework и всех серверов: изменение затрагивает ответы многих
инструментов. Прогнать полный `npm run validate:quiet` и разобрать каждый упавший снапшот
— падение может оказаться правильным новым поведением, а может быть регрессией.

## Definition of Done
- [ ] Тесты: пустая проекция → ключа нет; пустое значение из API → ключ сохранён
- [ ] Полная валидация монорепо зелёная, изменения снапшотов объяснены в отчёте

## Границы (файлы)
`packages/framework/core/src/utils/response-field-filter.ts` и его тесты; правки
упавших ожиданий в тестах других пакетов — только по факту, со списком в отчёте
