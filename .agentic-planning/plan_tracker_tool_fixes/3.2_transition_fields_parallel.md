# Этап 3.2 (PARALLEL) — transition_issue: параметр fields не работает

## Проблема
При запросе `fields: ["key","status.display"]` возвращается `"issue": {}`. Агент вынужден
делать отдельный `find_issues`, чтобы убедиться в результате перехода.

## Решение (развилка — выбирает исполнитель, обосновав в отчёте)
1. Дочитывать задачу после перехода и применять проекцию — дороже на один запрос,
   но соответствует объявленному контракту.
2. Убрать `fields` из схемы — честнее, но лишает агента подтверждения результата.
Предпочтение: вариант 1, если ответ API перехода не содержит нужных полей; вариант 2
допустим только при доказательстве, что дочитывание неуместно.

- [ ] Тест: запрошенные поля присутствуют в ответе после успешного перехода
- [ ] Тест: пустой объект больше не возвращается ни при каком наборе `fields`
