# Этап 2.4 (SEQUENTIAL, после 2.1–2.3) — контрактный тест «ответ валиден по своей outputSchema»

## Проблема
Дефект №1 не ловился ни одним тестом, потому что сервер `structuredContent` не валидирует
(`build-mcp-server.ts:195` отдаёт результат как есть) — валидация живёт только у клиента.
Дыра классовая: любая рассинхронизация схемы и рантайма проходит CI.

## Решение
Тест по таблице `0_enumeration.md`: для каждого batch-инструмента прогнать выполнение с
замоканным фасадом, где часть элементов падает с `ApiErrorClass` (404 и 409), и проверить,
что `structuredContent` проходит валидацию по `outputSchema` этого же инструмента.

## Definition of Done
- [ ] Тест покрывает все инструменты из таблицы, а не выборку
- [ ] Тест падает на откате любого из пакетов 2.1/2.2 (проверить руками через `git stash`)
- [ ] Успешный сценарий (0 ошибок) тоже проверяется — чтобы тест не «зеленел» вхолостую
