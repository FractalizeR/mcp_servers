# Этап 2.2 (PARALLEL, после 1.1) — чеклисты: deadline и контракт ошибки

## Проблема
`add_checklist_item` и `update_checklist_item` падают при любом значении `deadline`.
`AddChecklistItemInput` уходит в POST как есть (`add-checklist-item.operation.ts:65`),
т.е. `deadline` уходит строкой. API Трекера ждёт объект `{date, deadlineType}` —
подтверждено референсным клиентом: `collections.py:1949-1952` (строка оборачивается) и
`tests/smoke/entities/test_entities_checklists.py:11-13`.

## Решение
1. Обёртка строки в объект на границе API-операции (не в схеме — схема остаётся
   агент-дружественной строкой ISO 8601), симметрично `key-result-body.util.ts`.
   Оформить общей утилитой построения тела, а не копипастой в add и update.
2. Описание параметра `deadline` в схеме обязано называть принимаемый формат.
3. Заодно перевести 4 схемы чеклистов на `BatchErrorValueSchema` из пакета 1.1.

## Кейсы
- `deadline: "2026-08-25"` → `{date: "2026-08-25", deadlineType: "date"}`
- `deadline: "2026-08-25T00:00:00.000+0000"` → та же обёртка, дата не переформатируется
- `deadline` не указан → ключ в теле запроса отсутствует (не `null`, не пустой объект)
- update без `deadline` → поле не затирается
