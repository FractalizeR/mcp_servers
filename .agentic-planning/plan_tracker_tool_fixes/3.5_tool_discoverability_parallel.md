# Этап 3.5 (PARALLEL) — обнаружимость инструментов в поиске клиента

## Проблема (диагностика пользователя, воспроизведена вживую)
Поиск инструментов на стороне клиента не находит `get_issues` в топе даже по точному
имени; русские запросы не находят ничего, хотя все описания на русском. Худший случай —
самое короткое описание на сервере: `[Issues/Read] Получить задачи`.

## Что здесь можно, а чего нельзя
Скоринг живёт в клиенте и нам недоступен — «починить поиск» нельзя. Управляемо ровно
одно: текст, который индексируется. Гипотеза — короткое бедное описание систематически
проигрывает многословным соседям; проверяема только вживую, после правки.

## Решение
1. Перечислить все инструменты с описанием короче порога — таблицей на диск, до правок.
2. Обогатить описания: назначение, когда предпочесть соседний инструмент, и английские
   ключевые слова рядом с русским текстом (эмбеддинг клиента англоязычный).
3. Правки массовые и однотипные → скриптом, а не вручную. Категории `[Issues/Read]`
   сохраняются — они уже работают.

## Definition of Done
- [ ] Таблица «инструмент × длина описания × что добавлено» на диске
- [ ] `npm run validate:docs` и `npm run validate:tools` зелёные
- [ ] Правки только в `*.metadata.ts` — ни одного изменения в схемах и тулах

## Границы (файлы)
`packages/servers/*/src/**/*.metadata.ts`

## Проверка эффекта
Только вживую после перезапуска MCP-сервера: контрольные запросы `issues`, `get_issues`,
«получить задачи» с limit 5 и 20. Результат до/после зафиксировать в отчёте.
