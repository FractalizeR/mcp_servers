# Этап 3.3 (PARALLEL) — ложный hasNextPage

## Проблема
`hasNextPage` выводится из `Link rel="next"` (`tracker-paginator.util.ts:145`), а Трекер
на курсорных ручках отдаёт этот заголовок всегда. Итог: `count: 1, hasNextPage: true`
стабильно во всех вызовах `get_comments`; агент с `fetchAll` делает лишний круг.

## Решение
Сверять признак следующей страницы с фактическим числом элементов страницы: если вернулось
меньше запрошенного `perPage` — следующей страницы нет, независимо от заголовка.
Осторожно: `truncated` (обрыв по `maxItems`) обязан продолжать держать `hasNextPage=true`.

## Кейсы
- элементов меньше `perPage` + есть Link → `hasNextPage: false`
- элементов ровно `perPage` + есть Link → `hasNextPage: true`
- `truncated: true` → `hasNextPage: true` при любом числе элементов
- `perPage` не задан (дефолт API) → поведение зафиксировать тестом, не угадывать
