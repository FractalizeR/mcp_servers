# Этап 1.1 (SEQUENTIAL, блокирует 2.1–2.3) — общий контракт ошибки batch-элемента

## Проблема
`BatchResultProcessor.process()` кладёт в `failed[].error` либо строку, либо объект
`ApiErrorClass.toJSON()`. Все 17 схем трекера объявляют это поле как `z.string()`.
Клиент MCP валидирует `structuredContent` по `outputSchema` → при любом частичном отказе
успешный ответ отбрасывается и агент видит `Tool execution failed`. Побочный эффект:
операции записи (add_comment, add_worklog, create_link) выглядят проваленными, будучи
выполненными → ретрай агента порождает дубли.

## Решение
Один разделяемый контракт значения ошибки, на который переходят все схемы.

## Контракты
- `packages/servers/yandex-tracker/src/common/schemas/output.schema.ts`:
  - `BatchErrorValueSchema` — union строки и объекта деталей API-ошибки
    (`statusCode`, `message`, опциональные `errors`, `retryAfter`); объект допускает
    неизвестные ключи, т.к. `ApiErrorDetails` расширяем.
  - `makeBatchErrorItemSchema(keyField)` — существующая фабрика, поле `error` меняет тип
    на `BatchErrorValueSchema`; сигнатура возвращаемого типа обновляется соответственно.
  - Экспорт через `#common/schemas/index.js`.
- Тип-ориентир: `ApiErrorDetails` из `@fractalizer/mcp-infrastructure` — схема обязана
  описывать ровно то, что возвращает `ApiErrorClass.toJSON()`.
