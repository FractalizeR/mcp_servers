# Этап 2 — Перевод эндпоинтов на cursor (PARALLEL, после 1.1)

5 групп по непересекающимся наборам файлов → можно исполнять разными агентами в
разных ветках одновременно. Каждая группа правит ТОЛЬКО свои 4 файла на эндпоинт
(schema/tool/operation/dto) + свои тесты. Общие контракты из 1.1 не трогать.

## Общий паттерн изменения для КАЖДОГО эндпоинта (без кода)

1. **Schema**: добавить `cursor` (`CursorSchema`) + refine `noCursorWithBulkParams`
   (R9); для batch — ещё `cursorRequiresSingleIssue` (R1). `page`/
   `noPageFetchAllConflict` пока НЕ удалять (deprecated до 3.1, R5).
2. **DTO**: добавить `cursor?: string` (page оставить deprecated).
3. **Operation**:
   - Если задан `cursor` → `CursorCodec.decode(cursor, <endpointTag>)` (БРОСАЕТ при
     невалидном/чужом/битом — R3/R13, НЕ тихий fallback) → запрос ПО декодированному
     пути напрямую (perPage/filters уже в нём).
   - Иначе → построить путь первой страницы БЕЗ `page` (только `perPage` + фильтры).
   - `singlePage`/`fetchAllPages` по контракту 1.1 (paginator сам считает hasSeek;
     операция передаёт `tag` для кодирования nextCursor).
4. **Tool**: пробросить `pagination.nextCursor`; УБРАТЬ эхо `page` (top-level и в
   meta) — см. R14, перечислить удаляемые output-поля для своего эндпоинта.
5. **Кеш (R10)**: где есть selective-cache (links и др.) — добавить `cursor` в
   условие bypass (`hasPaginationParams || cursor !== undefined`).
6. **Тесты**: обновить (убрать page-кейсы); регрессия курсорного листания через
   MockHttpClient (ответ с `Link: <...id=...>; rel="next"` → второй запрос идёт по
   ДЕКОДИРОВАННОМУ пути и отдаёт СЛЕДУЮЩИЕ записи); тест `decode`-ошибки на битом
   курсоре; контракт-тест ответа (нет `page`).

### Правило для непагинируемых эндпоинтов (components, attachments; checklist/worklog — по верификации)
- УБРАТЬ из схемы/DTO: `cursor`, `perPage`, `fetchAll`, `maxItems`, `maxTotalItems`.
- Operation: один запрос без пагин-параметров; вернуть все элементы.
- Tool-ответ: БЕЗ блока `pagination` (либо явный маркер `paginated:false` —
  выбрать единый стиль в 1.1/ревью и применить одинаково).
- Тесты: обновить — убрать пагин-кейсы; проверить, что все элементы приходят.
- ⚠️ Перед удалением у `worklog`/`checklist` — обязательная проверка на реальных
  данных (>perPage записей) или по офиц. доке API; при сомнении НЕ удалять.

## Группа 2.5 — find_issues (POST `_search`, самый сложный) — отдельный агент
- Файлы: `tools/api/issues/find/{find-issues.schema.ts,find-issues.tool.ts}`,
  `tracker_api/api_operations/issue/find/find-issues.operation.ts`,
  `tracker_api/dto/issue/find-issues-input.dto.ts`.
- `cursor` вместо `page`. Первая страница: POST `_search` c `perPage` (+expand),
  тело из критериев (query/filter/keys/queue/filterId/order).
- **Курсор `_search` кодирует next-путь + ХЕШ канонического тела (R2).** Ручное
  листание: критерии передаются повторно; операция канонизирует их → считает хеш →
  СВЕРЯЕТ с хешем в курсоре. Mismatch → explicit error (не тихий мусор). При совпадении —
  replay `postWithResponse(decodedPath, rebuiltBody)`.
- `expand` (R2): в Link его нет → при курсоре передаётся повторно и дописывается
  к декодированному пути.
- refine: при наличии `cursor` критерии ОСТАЮТСЯ обязательными (нужны для replay
  тела); конфликт `cursor`+`perPage/fetchAll/...` по `noCursorWithBulkParams`.
- `fetchAll`: обход по `Link rel="next"`; fallback `fetchByPageNumbers` по
  `X-Total-Pages` — РЕШИТЬ: т.к. `_search` всегда отдаёт `Link rel="next"` при
  наличии данных (подтверждено), ветка вероятно мёртвая → либо удалить, либо
  оставить со страховочным тестом достижимости (M2/Codex). Сохранить `maxPages`.
- seek-gating: у `_search` seek есть → `total`/`totalPages` остаются.
- pagination остаётся соседним полем (НЕ оборачивать issues). Убрать top-level эхо
  `page`/`perPage` из ответа (R14).

## Edge cases (для всех групп)
- `cursor` от другого эндпоинта (путь не той сущности) → guard `/v[23]/` пройдёт,
  но это ответственность агента; декодированный путь используется как есть.
  (Защита: путь всё равно валидируется префиксом; кросс-эндпоинт-курсор — UB,
  задокументировать «курсор использовать только с тем же инструментом».)
- Пустая коллекция → `hasNextPage=false`, без `nextCursor`.
- Последняя страница seekable (queues) → сервер не отдаёт `rel="next"` →
  `hasNextPage=false` (подтвердить тестом, что обход терминируется).
