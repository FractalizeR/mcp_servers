# @fractalizer/mcp-dev-client

Тонкий dev-интерфейс: вызвать MCP-инструменты сервера этого монорепо ровно
так, как их вызовет настоящий MCP-клиент, — без регистрации агента,
дорабатывающего код, как ещё одного MCP-клиента и без перезапуска сессии
между вызовами.

`private: true` — пакет не публикуется в npm. Каждый из трёх серверов
(`yandex-tracker`, `yandex-wiki`, `ticktick`) подключает его как
`devDependency` и вызывает через npm-скрипты `tools:list`/`tools:call`/`tools:batch`
(добавляются npm-скриптами конкретного сервера, см. его `README.md`).

Полное обоснование архитектуры и разбор альтернатив —
[`.agentic-planning/plan_mcp_dev_interface/README.md`](../../../.agentic-planning/plan_mcp_dev_interface/README.md)
в корне монорепо (пока план не удалён после завершения всех его пакетов).

## Зачем

Агент дорабатывает код сервера в git worktree, а токены и адрес API сервера
знает только запись подключения в MCP-клиенте (`claude mcp get <name>`).
`mcp-dev`:

1. Резолвит **локально собранный бандл текущего рабочего дерева**
   (`package.json` → `bin` пакета сервера, а не путь из записи клиента —
   та указывает на основной checkout, не на worktree агента).
2. Берёт из записи клиента **только `env`** (секреты) — не команду, не путь.
3. Открывает одну stdio MCP-сессию, прогоняет один или несколько вызовов,
   печатает результаты в stdout построчно (JSONL), закрывает сессию.

## Команды CLI (`mcp-dev`)

```
mcp-dev list  --server-name <n> --package-dir <dir> [--json] [--writable]
mcp-dev call  <tool> <json|@file> --server-name <n> --package-dir <dir> [--dangerously-allow-write]
mcp-dev batch <file.jsonl>       --server-name <n> --package-dir <dir> [--dangerously-allow-write] [--stop-on-error] [--delay-ms <n>] [--call-timeout-ms <n>]
```

- `--server-name` — имя сервера **как оно записано в MCP-клиенте** (например,
  `fractalizer_mcp_yandex_tracker`). Задаётся npm-скриптом сервера, не хардкожено
  в этом пакете — framework не может знать имена серверов (это было бы обратным
  ребром графа зависимостей монорепо).
- `--package-dir` — каталог пакета сервера в **текущем** рабочем дереве
  (обычно `.` из npm-скрипта самого сервера).
- `call` — частный случай `batch` из одной строки: строит ту же JSONL-строку,
  что попала бы в файл батча, и прогоняет её тем же кодом. Отдельного пути
  исполнения нет.
- `--dangerously-allow-write` читается **только** из аргументов командной
  строки — из переменных окружения никогда, чтобы флаг нельзя было
  «прилепить» к окружению сессии агента.

### Формат батча (JSONL, одна строка — один вызов)

```jsonl
{"tool": "fr_yandex_tracker_get_issues", "args": {"issueIds": ["PROJ-1"], "fields": ["id", "summary"]}}
{"tool": "fr_yandex_tracker_find_issues", "args": {"query": "Queue: PROJ"}, "label": "smoke", "expect": {"isError": false}}
```

Имя инструмента — всегда с префиксом сервера (`fr_yandex_tracker_`, `yw_`, `fr_ticktick_` —
`MCP_TOOL_PREFIX` в `src/constants.ts` конкретного сервера); фактический список — `mcp-dev list`.

- `label` — опциональная метка строки для читаемости вывода.
- `expect.isError` / `expect.contains` — опциональная проверка результата;
  несовпадение попадает в `expectationMet: false` и делает код возврата `1`.

## Классификация инструментов

- **read** — `readOnlyHint === true` и в схеме аргументов нет свойства,
  похожего на путь локальной ФС (`/path/i` в имени top-level свойства).
- **write** — `readOnlyHint !== true` (именно "не равно true": отсутствие
  аннотации трактуется как запись — консервативный дефолт).
- **local-side-effect** — `readOnlyHint === true`, но инструмент пишет файл
  на диск (например, `download_attachment` с `saveToPath`). `readOnlyHint`
  по спецификации MCP говорит только про отсутствие сетевых побочных
  эффектов, ничего не говорит про запись на диск разработчика.

`write` и `local-side-effect` без `--dangerously-allow-write` не выполняются:
проверка идёт по всему батчу **до** первого `tools/call` — если хоть одна
строка нарушает политику или ссылается на неизвестный инструмент,
не отправляется ни одна.

Классификация опирается не только на `readOnlyHint` — сверка аннотаций всех
153 инструментов трёх серверов против фактического поведения кода:
[`docs/tools-annotations-inventory.md`](docs/tools-annotations-inventory.md).

## Вывод и коды возврата

- **stdout** — только JSONL результатов (`list --json` — исключение, печатает
  один JSON-массив, а не построчно). Это то, что читает агент.
- **stderr** — человекочитаемые сообщения: ошибки, сводка вызовов/провалов.

| Код | Значение                                                                                                                                                                                              |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0` | Все вызовы прошли, все `expect` (если заданы) сошлись                                                                                                                                                 |
| `1` | Есть провал: несошедшийся `expect`, `isError: true` без явного `expect`, или отказ политики записи (в этом случае `tools/call` не отправляется вовсе ни для одной строки батча)                       |
| `2` | Сессия не открылась: сервер не подключён в MCP-клиенте, бандл не собран, устарел или его свежесть не проверяема (каталог вбандленной `@fractalizer/*`-зависимости не найден), handshake не завершился |

## Контур секретов

Токен MCP-сервера маскируется в сообщениях `mcp-dev`, включая необработанные
исключения, — цель в том, чтобы он не попадал в контекст агента **по
неосторожности** через вывод этого интерфейса.

Что именно считается секретом, решает одна шкала (`src/secrets/sensitivity.ts`),
общая для записи MCP-клиента и родительского окружения: имя ключа (`*_TOKEN`,
`*_SECRET`, `*_PAT`, `*_PWD`, `*_COOKIE`, `SESSION*`, `*_DSN`, …) **и** форма
значения (connection-строка с парой `user:pass@`, PEM-заголовок приватного
ключа, JWT — их именем ключа не поймать). Заведомо несекретные ключи записи
(`LOG_LEVEL`, `*_TIMEOUT`, `*_API_BASE`, `*_ORG_ID`, `*_CLIENT_ID`,
`*_REDIRECT_URI`) под маску не попадают: `YANDEX_ORG_ID` — семизначное число,
случайно совпадающее с числами в тексте тикетов, и его маскирование делало
ответ сервера искажённым и неотличимым от бага. Неопознанный ключ **записи
клиента** маскируется (консервативный fallback: имена переменных конкретного
сервера заранее не известны), неопознанный ключ родительского окружения — нет. Это **не** граница доверия:
у агента и так есть Bash и он может прочитать токен напрямую
(`claude mcp get <name>`) или из исходников сервера — от намеренного чтения
маскирование не защищает.

## Устройство пакета

| Каталог             | Предмет                                                                                             |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| `src/launch/`       | Резолв запуска: локальный бандл (+ свежесть) + `env` из записи клиента                              |
| `src/session/`      | MCP-сессия: открыть, `listTools`, `callTool`, закрыть                                               |
| `src/secrets/`      | Маскирование значений `env` во всём выводе + guard необработанных исключений                        |
| `src/write-policy/` | Классификация read/write/local-side-effect + допуск батча                                           |
| `src/batch/`        | Разбор JSONL, прогон в одной сессии, агрегация                                                      |
| `src/cli/`          | Адаптер доставки — разбор argv, три команды, вывод (этот пакет — тонкая обёртка над всем остальным) |

`src/cli/` не экспортируется через `src/index.ts` пакета: это не библиотечный
API, а реализация единственного бинарника `mcp-dev` (`package.json` → `bin`).

## Тесты

- `npm test` — юнит-тесты (включая `tests/cli/`) на заглушках: без реального
  спавна процесса (`transportFactory`) и без реального `claude` CLI
  (`connectorFactory`).
- `npm run test:integration` — реальный MCP handshake против реально
  собранного бандла; требует `claude` CLI и подключённую запись сервера.
  Не входит в `validate`/`validate:quiet`.
