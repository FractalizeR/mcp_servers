## Что сделано и зачем

Повод: `POST /v3/boards` не отвечал ошибкой — он создавал доску с параметрами по
умолчанию, молча игнорируя тело. Мина найдена случайно; проверялось, нет ли таких же.

1. **Инструмент сплошной сверки** — `scripts/sweep-doc-routes.ts`, команда
   `npm run sweep:doc-routes`. Скачивает 156 страниц справочника API Трекера,
   структурно извлекает метод и путь, сверяет с `outgoing-requests.md`.
2. **Починка контрактов, подтверждённых живыми пробами по боевому API:**
   - `update_project`, `update_component` отвечали `428` — не слали обязательную
     версию, то есть НЕ РАБОТАЛИ НИКОГДА. Версия теперь уходит в `?version=`;
     не передана вызывающим — операция читает текущую сама;
   - `update_project` с `queueIds` получал `400`; очередь и там, и там — `queues`;
   - `update_board` слал `filter: {query}` и получал `422`; форма фильтра — карта
     «поле → значения»; `orderBy`/`orderAsc` без `filter` отклоняются до запроса;
   - `create_queue`: убран `issueTypes` (`400` на любой вызов с ним);
   - `update_board`: убран `version` (`400` на любое значение).
3. **Удалены `delete_component` и `delete_global_field`** — маршруты не объявлены
   ни справочником, ни референсным клиентом, выведены из `Collection.delete()`.
4. **Удалено легаси-семейство `/v3/projects`** (5 инструментов, ресурс, промпт) —
   справочник помечает раздел «старая версия», живая проба показала, что легаси и
   Entity API дают ОДИН набор объектов (43 = 43, пересечение имён 39 из 39).
   Категория `projects` теперь означает Entity API и убрана из отключённых по
   умолчанию в манифесте.
5. Инструментов 92 → 85.

## На что смотреть в первую очередь

- **Швы между тремя пакетами удаления и починки.** Файлы, которые трогали и то и
  другое: `src/tracker_api/facade/yandex-tracker.facade.ts`,
  `src/composition-root/definitions/{tool,operation}-definitions.ts`,
  `src/live_scope/organization-rules.ts`, `tests/live_scope/known-mutating-requests.ts`,
  `CLAUDE.md`, `README.md`, `tests/coverage-exceptions/legacy-mock-tests.ts`.
  Вопрос ревьюеру: **какую форму входа не покрыл ни один пакет?**
- **Снятие правила `/v3/projects` из рубежа живого прогона.** Обоснование: рубеж
  fail-closed, `RAW_API_METHODS = ['GET']`, значит мутирующий запрос к этому пути
  не может исходить ни от одного инструмента. Проверьте рассуждение и то, не открыло
  ли снятие дыру.
- **Переписанные тесты рубежа.** 12 файлов адаптированы с легаси-проектов на другие
  семейства (globalField/board/filter). Не выхолощены ли проверки, сохранилось ли
  покрытие механик (fail-closed, дуальная адресация id/key, ссылки на людей в теле).
- **Чтение версии перед PATCH** в `update-project.operation.ts` и
  `update-component.operation.ts`: лишний GET, гонка, поведение при отсутствии
  `version` в ответе, влияние на кеш.
- **Скрипт сверки** `scripts/sweep-doc-routes.ts`: разбор HTML регулярками,
  обработка обрывов сети, ложные срабатывания и ложные пропуски, `LIVE_VERIFIED_KEYS`
  как способ гасить уже закрытые расхождения.
- **Удаление промпта `project-summary` и ресурса `tracker://project/{id}`** —
  осознанная потеря возможности; оцените, не стоило ли перенести на Entity API.
